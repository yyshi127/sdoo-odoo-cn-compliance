# 里程碑 18：可解释税务影响与增值税调节报告

## 目标

解决“勾稽差异不等于税务影响、多个差异可能重复描述同一税额”的核心问题，在规则结果和增值税四方勾稽之上增加受控人工量化层，并输出可追溯的单批次增值税调节与税务影响报告。

交付版本：`sudo_country_pack_cn 19.0.1.16.0`。

## 受控税务影响事项

新增模型 `sudo.cn.tax.impact.case`。一份复核事项代表一个经济影响，可以同时关联：

1. 同一规则评估中的一条或多条失败、待确认或错误结果。
2. 同一增值税勾稽批次中的一条或多条数据问题、控制问题或金额差异。

同一规则结果或勾稽问题只能归入一份未取消事项。保存时会锁定来源记录并检查其他未取消事项，避免两个并发编制流程把同一来源重复计量。取消已复核事项后，可以基于同一来源建立新的受控版本，历史事项仍保留。

## 金额语义

系统不提供“净风险金额”，而是使用两个相互独立的维度：

| 维度 | 状态 |
| --- | --- |
| 影响方向 | 尚未判断、复核后无税额影响、期间错配、潜在少缴、潜在多缴 |
| 量化状态 | 尚未评估、现有证据无法量化、待复核初步金额、已复核金额 |

金额必须是非负绝对值，由影响方向表达性质。只有同时满足以下条件的事项进入报告金额汇总：

- 工作流状态为“已复核”。
- 量化状态为“已复核金额”。
- 最终复核 SHA-256 与当前来源、附件和复核意见一致。

潜在少缴、潜在多缴和期间错配分别汇总，不相互抵销。无法量化事项保留数量和专业说明，但金额为零；草稿、待复核和完整性异常事项不进入金额合计。

## 工作流与职责分离

工作流为：

`分析中 -> 待独立复核 -> 已复核 -> 已取消`

提交复核前必须满足：

- 至少关联一项规则风险或勾稽问题。
- 规则风险已经完成人工确认或被标记为需要整改。
- 关联评估已经完成，关联勾稽批次是成功或已被新结果替代的审计快照。
- 期间、档案、公司和来源完全一致。
- 已填写不少于 20 字的事实分析和计算过程。
- 已填写假设、限制与不确定性、工作底稿引用。
- 已上传系统内非空二进制证据。
- 已选择“待复核初步金额”或“现有证据无法量化”。

确认复核前，复核人必须填写不少于 20 字的独立复核意见。编制人与复核人为同一人时，必须额外记录不少于 20 字的受控例外理由。普通合规用户按允许公司只读；合规管理员才可以编制和执行状态操作。所有创建、修改、提交、复核、退回和取消均写入不可改写审计事件。

## 完整性控制

提交 SHA-256 绑定：

- 档案、公司、币种和期间。
- 关联评估及增值税勾稽批次。
- 规则结果校验和、人工复核状态和复核意见哈希。
- 勾稽问题代码、金额和批次结果校验和。
- 影响方向、量化状态、金额、计算过程和限制。
- 工作底稿引用、编制人和全部证据附件内容。

最终复核 SHA-256 在上述载荷之外继续绑定复核人、复核时间、复核意见和职责分离例外。来源复核状态、勾稽结果或附件内容后续变化时，事项显示“资料已变化”，相关金额立即退出评估和勾稽报告汇总，不会保留失效金额。

## 原生用户体验

- 在 Odoo 合规管理下新增“税务影响复核”菜单。
- 规则风险、增值税勾稽问题、勾稽批次和合规报告都提供原生入口与统计按钮。
- 表单使用标准状态栏、警示信息、分组、标签页、徽章和附件控件。
- 影响方向、量化状态、金额、来源数量、复核人和完整性在列表中直接可见。
- 合规报告和勾稽批次分别展示待复核、已复核、无法量化、完整性异常及三类金额。
- 混合方向的事项列表不提供金额合计，防止界面再次产生隐含净额。

规则与配置继续沿用 Odoo 原生管理界面；本里程碑没有引入独立前端框架或脱离 Odoo 权限上下文的页面。

## 增值税调节与税务影响报告

新增单批次 QWeb PDF，内容包括：

1. 公司、期间、勾稽结论、账务比较口径和结果 SHA-256。
2. 账务、电子发票、增值税申报和税款缴纳的数据准备状态。
3. Odoo 发票税额、控制科目、已批准申报调整、账务申报比较口径、受控电子发票和受控申报之间的调节链。
4. 申报应纳税额、有效缴税净额及两者差异。
5. 每项原始勾稽问题及左右口径，不设置差异总计。
6. 待复核、已复核、无法量化和完整性异常数量。
7. 潜在少缴、潜在多缴和期间错配三类已复核金额。
8. 每份影响事项的来源数量、工作底稿、复核人、完整性和复核 SHA-256。

报告绑定被显式关闭，只能从单个成功勾稽批次打印，避免服务器未补丁 Qt 对多文档合并的限制。报告醒目标记其为受控工作底稿，不是申报表、税务机关认定或法律意见。

## 自动化验收

新增运行时场景覆盖：

- 来源、证据、分析和复核门禁。
- 初步金额不进入汇总。
- 少缴、多缴和期间错配分别汇总且无净额字段。
- 无法量化事项只计数量、不计金额。
- 同一来源禁止重复归并，取消后允许形成新版本。
- 同人复核例外。
- 提交后证据篡改阻断复核。
- 最终复核后证据篡改使金额退出汇总。
- 期间一致性、普通用户只读和多公司记录隔离。
- 风险结果到影响事项的原生动作。
- QWeb 报告边界、结果哈希和复核哈希。

最终结果：

- 本地 Python/XML 编译、静态契约和数据契约测试通过。
- 隔离空库新装执行 `146` 个运行时测试方法，Odoo 统计 `166` 项，`0 failed / 0 errors`。
- 从 `19.0.1.15.0` 基线升级后执行同一全量测试，`0 failed / 0 errors`。
- 真实数据副本升级后仍有 `15,589` 张会计凭证和 `44,651` 条会计分录。
- 原增值税勾稽结果仍为 `succeeded / insufficient_data / invoice_tax_totals`，发票销项税额 `5.18`，原结果 SHA-256 保持不变。
- 七项来源仍全部待独立复核，七份专业复核包和十四条引用保持不变，没有专业签核或规则发布。
- 真实副本事务内完成事项创建、提交、复核、HTML 与单份 PDF 渲染，PDF 为有效 `%PDF`，完整流程约 `1.886` 秒。
- 人为篡改最终证据后，完整性异常数从 `0` 变为 `1`，已复核少缴汇总从 `1.23` 降为 `0.00`；事务随后回滚，真实副本未保留测试事项。

## 当前边界与下一步

本里程碑解决了差异归并、人工量化、职责分离、完整性失效和报告分列问题，但没有生成任何真实企业税务结论。七项官方来源仍需由不同人员取得并逐页核实官方原文，七条候选规则仍需真人中国财税专业签核和技术审批。可选 XBRL 插件仍需单独完成隔离 Odoo 运行时安装验收；后续还需继续完善正式合规报告体系和更大数据量性能基线。
