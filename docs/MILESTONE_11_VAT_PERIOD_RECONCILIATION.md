# 里程碑 11：增值税期间四方勾稽

## 目标

在受控数据来源已经建立的基础上，按同一中国合规档案和税款所属期，比较 Odoo 账务、电子发票、增值税申报和税款缴纳四类数据，形成可解释、可追溯、不可改写的期间勾稽结果。

本里程碑只回答“受控口径之间是否具备比较条件、金额是否一致”。它不自动形成税务合规、税务风险、少缴税或违法结论，也不自动修改会计凭证、申报记录或缴款记录。

## 交付范围

- 中国国家包版本升级为 `19.0.1.9.0`。
- 新增增值税期间勾稽批次、勾稽问题和发起向导。
- 新增两分钟一次、每次最多处理一个批次的原生 Odoo 后台队列。
- 新增批次、问题和发起勾稽的原生 Odoo 菜单及清晰的结果页面。
- 新增 `19.0.1.9.0` 升级迁移，安全更新中国国家包运行态元数据。

## 四类数据口径

### Odoo 账务

当前版本汇总期间内 Odoo 已过账客户发票、客户退款、供应商账单和供应商退款的公司本位币发票税额合计。退款按相反方向冲减。草稿发票保留在审计范围并生成复核提示，但不计入税额。

`amount_tax_signed` 反映 Odoo 发票上的全部税额，并不是已经按中国增值税税种、税目或控制科目完成映射的专用口径。系统会固定显示该方法限制，因此当前阶段即使四方金额一致也仍是带警告的一致结果。

该口径不是完整的增值税总账控制科目分析，暂不包含手工总账税额调整、未开票收入、视同销售、进项转出、留抵、加计抵减或其他申报调整。因此，账务与申报差异必须由人员结合建议逐项解释。

### 电子发票

只读取已成功解析、数据集仍处于封存状态且完整性校验有效的当前规范化结果。系统使用公司统一社会信用代码判断销项和进项，红字税额反向冲减。

以下情况会阻断电子发票总额比较：

- 公司缺少统一社会信用代码。
- 主体无法归类、币种不一致、税额缺失或红蓝状态不明。
- 当前范围存在重复发票。
- 数据质量错误、声明数量不一致、完整性失效或不是完整覆盖。
- 真实性受控验证明确失败。

### 增值税申报

勾稽期间必须恰好存在一份当前有效申报。系统不自动猜测多份申报或更正申报中的最终版本。有效状态限于已申报、已受理和更正申报，并要求提供销项税额、进项税额和应纳税额。

### 税款缴纳

按向导中的增值税税种代码筛选同一所属期的当前缴款记录。缴款成功按正数计入，冲正和退库按负数冲减，处理中和失败记录不计入并生成复核提示。重复、币种不一致、金额缺失、数据质量错误或没有任何有效缴款会阻断申报与缴税比较。

## 五项金额比较

只有相关来源可比较时，系统才计算以下差异：

1. Odoo 账务销项税额与电子发票销项税额。
2. Odoo 账务进项税额与电子发票进项税额。
3. Odoo 账务销项税额与增值税申报销项税额。
4. Odoo 账务进项税额与增值税申报进项税额。
5. 增值税申报应纳税额与有效缴税、冲正及退库净额。

每项非零差异保存稳定问题代码、左右口径、左右金额、差额和建议下一步。数据缺失或控制失效时不计算伪差异，也不会把缺失金额当作零值通过。

## 结论状态

- `数据不足`：至少存在一项阻断问题，不能形成四方金额一致或不一致结论。
- `存在差异`：所有必要来源可比较，但至少存在一项金额差异。
- `勾稽一致`：所有可要求的比较均为零差异。页面明确显示“四方勾稽一致，不等于合规结论”。

真实性尚未确认、单人复核例外、草稿凭证或非生效缴款等非阻断警告仍会显示。即使金额一致，也不会隐藏这些限制，页面会使用警告状态而不是纯成功状态。

## 版本、队列与审计

- 同一档案和期间同时只能存在一个待处理或处理中的批次，数据库部分唯一索引负责并发兜底。
- 队列使用 `FOR UPDATE SKIP LOCKED`，避免多个工作进程重复领取同一批次。
- 失败重跑不会替代上一份成功结果；新成功结果才会将旧成功结果标记为已被替代。
- 批次和问题只能由受控引擎创建或更新，用户不能修改、复制或删除审计结果。
- 账务、电子发票、申报和缴税分别生成 SHA-256 快照指纹。
- 结果指纹覆盖引擎版本、期间、来源状态、记录数量、来源指纹、金额、提供状态和稳定排序的问题代码。
- 排队、处理中、失败、成功、取消和替代均写入合规审计事件。
- 成功结果是执行时点快照，不是实时结论；后续账务或来源变化不会改写旧审计记录，必须重新发起勾稽形成新版本。

## 权限与多公司

- 普通合规用户只读；合规管理员可以发起和取消尚未执行的批次。
- 批次和问题按 Odoo 当前允许公司隔离。
- 聚合税额和差异可供合规角色查看；底层 Odoo 会计凭证明细同时要求会计只读权限。
- 引擎只在受控落库步骤提权写入会计快照关联，用户不能借此绕过字段权限读取凭证明细。

## 页面体验

批次首页先展示四类数据源状态、记录数量、金额和五项差异，再展示按阻断、复核和提示排序的问题。不同结论使用独立提示带，并明确给出下一步建议。列表视图对失败、数据不足、存在差异、带警告的一致结果和无警告的一致结果采用不同视觉状态。

规则与配置继续使用 Odoo 原生界面；高频查看和复核页面在不违和的前提下强化信息层级和结论边界。

## 自动化校验

已编写 16 个 Odoo 运行时测试，覆盖受控创建、重复活动期间、取消、完整一致、可解释差异、来源缺失、部分覆盖、多份申报、缺少缴税、冲正净额、重复缴款、草稿凭证、失败重跑、成功替代、不可改写、队列和多公司权限。测试还验证普通合规用户不能读取底层会计凭证明细。

`tools/validate_addon.py` 已将模型导入、关键阻断及差异代码、快照指纹、审计事件、只读 ACL、公司规则、受限会计字段、队列、视图、菜单和最低运行时测试数量纳入持续门禁。

仓库现有纯 Python 校验已全部通过：13 项税务数据契约测试、9 项 XBRL 契约测试、4 项 XBRL 规范化测试和 3 项工作器兼容性测试。
