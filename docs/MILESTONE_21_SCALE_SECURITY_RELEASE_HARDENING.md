# 里程碑 21：规模、安全与发布加固

## 目标

在不改变勾稽结论、审计指纹和会计数据的前提下，降低真实账套规模下的发票台账索引内存占用，补齐正式报告的多公司与指定批准人对抗测试，并验证核心中国包的新装、升级和真实数据兼容性。

交付版本：`sudo_country_pack_cn 19.0.1.18.0`。

本里程碑是工程与发布加固，不发布中国税法规则，不替代真人中国财税专业签核，也不把候选规则转为真实企业合规结论。

## 性能基线

在 `odoo_2601` 的隔离副本中，最大中国公司具有 9,513 张可参与发票勾稽的会计凭证。基线测量结果如下：

- 21 项中国事实提取约 `0.068s`、60 次查询；7 项完整，14 项因受控外部来源不存在而明确返回缺失。
- 9,513 张候选凭证加载约 `0.011s`、2 次查询。
- 优化前台账索引与快照摘要构建约 `0.962s`、15 次查询、峰值内存增量约 `72.1 MiB`。
- 增值税期间勾稽约 `0.044s`、35 次查询；缺失受控来源时返回 `insufficient_data`，没有形成伪通过。
- 正式报告真实 QWeb/wkhtmltopdf 签发约 `2.19s`，生成有效 PDF 并通过内容、批准与 PDF 三重完整性校验。

这些数据用于识别工程热点，不是对任意硬件、任意期间或 10 万张凭证上限的容量承诺。超大数据量仍应按受控期间分批执行并监控 Odoo 进程内存、事务时间和队列积压。

## 台账索引优化

原实现为了生成整个账簿范围的 SHA-256，同时保留每张凭证的完整 Python 快照。真实样本中，这部分内存会随凭证数线性增长。

本版本进行了两项兼容优化：

1. 按凭证 ID 顺序流式写入规范 JSON 列表并计算 SHA-256，不再保留完整快照字典。
2. 关闭 `account.move` 的宽字段预取，只通过 Odoo ORM `fetch()` 一次性加载本次实际使用的 14 个字段，避免把无关字段装入环境缓存。

优化后同一 9,513 张凭证样本为：

- 约 `0.861s`。
- 7 次查询。
- 峰值内存增量约 `18.9 MiB`。
- 凭证数量、索引键数量和 64 位台账 SHA-256 均保持一致。

相较初始基线，峰值内存下降约 74%，查询次数由 15 降至 7，耗时下降约 11%。回归测试同时验证空台账和非空台账的新流式摘要与旧完整列表算法逐字节一致，因此历史审计指纹不会因本次优化改变。

## 正式报告安全加固

正式报告原有模型已经具备公司记录规则、批准人公司约束和指定批准人动作校验。本版本新增明确的对抗式运行时测试，验证：

- 只拥有其他公司权限的合规管理员搜索不到、也不能直接读取当前公司的正式报告。
- 不具有报告所属公司访问权的批准人不能被指定到报告。
- 同公司中具有批准权限但未被指定的人员，不能填写批准意见、退回报告或签发报告。
- 普通只读用户仍不能编制或改写报告。

正式报告测试类共执行 14 个方法，全部通过。业务模型未因测试而放宽任何访问控制。

## 发布与升级

- 清单、国家包元数据和安装数据版本统一提升到 `19.0.1.18.0`。
- 后迁移仅调用受控元数据更新，不创建报告、风险、规则或会计记录。
- 静态校验强制要求窄字段预取、流式摘要兼容测试、多公司隔离测试和指定批准人测试继续存在。
- 核心中国包隔离空库新装执行 161 个运行时测试方法，Odoo 统计 183 项，结果为 `0 failed / 0 errors`。
- 从 `19.0.1.17.0` 隔离基线升级后执行同一组测试，迁移日志确认后迁移运行，结果仍为 `0 failed / 0 errors`。
- 本地静态契约、Python/XML 编译及 31 项纯数据契约测试通过。

## 真实数据不变性

升级前后均对 `odoo_2601` 只读源库与隔离副本执行确定性比对。15,589 张会计凭证和 44,651 条会计分录的数量、借贷合计、凭证内容摘要及分录内容摘要完全一致。

测试没有修改共享底座、新加坡国家包、`odoo_2601`、主 Odoo 服务配置或生产 Python 依赖。主服务在整个验收期间保持运行。

## 当前边界

工程链路现已具备较完整的新装、升级、真实数据、性能、权限和审计验证，但产品仍不具备真人专业签核后的生效中国税法规则。七条规则继续保持候选状态；在官方来源独立复核、适用性判断、规则测试、技术批准和中国财税专业签核完成前，不得对真实企业宣称已经形成税法合规结论。
