# 里程碑 22：受控增值税申报与缴款档案

## 目标

补齐中国财税合规闭环末端的“申报与缴款档案”，同时避免在中国国家包中复制一套与通用底座冲突的申报生命周期。

交付版本：`sudo_country_pack_cn 19.0.1.19.0`。

本里程碑登记和封存已经依法取得的申报、缴款与回执证据，不连接税务机关，不自动申报或扣款，不自动推断法定期限，也不把档案状态、金额一致或系统校验解释为税务机关认定或税务合规结论。

## 架构

通用底座 `sudo.compliance.filing` 继续负责以下国家无关能力：

- 草稿、准备中、待提交、已提交、已受理、被退回和无需申报生命周期。
- 申报期间、负责人、官方截止日依据、提交参考号、回执和付款状态。
- 申报准备任务、正式证据和不可改写审计事件。
- 多公司记录规则及通用权限。

中国国家包只增加中国税务来源和控制：

- 将一份申报档案关联到同公司、同档案、完全相同期间的增值税四方勾稽批次。
- 读取勾稽批次中唯一的规范化增值税申报和受控缴款记录，不复制金额台账。
- 在申报与付款两个时点分别形成规范 JSON 快照和 SHA-256。
- 显示来源批次、标准化记录、已封存正式证据、缴款方向分列和完整性状态。

共享 `sudo_global_finance` 和新加坡国家包没有被修改。

## 申报门禁

中国增值税档案进入待提交和登记已提交前必须同时满足：

1. 档案关联 `CN-VAT` 义务，义务已经完成公司级适用性确认，在当前期间有效，并绑定仍然有效的官方原文快照。
2. 截止日期由用户人工确认，绑定有效官方来源并填写计算说明；系统动作上下文不提供默认截止日或默认截止日依据。
3. 勾稽批次是当前成功结果，申报来源状态可用且具有结果与申报快照校验和。
4. 当前期间只有一份受控申报记录，来源文件完整、数据质量无错误，状态为已申报、已受理或更正申报。
5. Odoo 实际提交日期和官方参考号与受控申报记录一致。
6. 至少一份类型为申报回执或外部受控档案的正式证据已经完成验证，且当前文件指纹仍与验证时 SHA-256 一致。

普通二进制附件仍可作为补充资料，但不能替代正式证据门禁。

## 缴款门禁

标记全部已付款前必须同时满足：

- 档案已提交或已受理，且明确标记需要付款。
- 受控缴款来源可用，至少存在一条缴款成功记录；来源完整性、主体、期间、币种和数据质量通过控制。
- 申报应纳税额与缴款成功减冲正、减退库后的有效净额勾稽一致。
- 实际付款日期等于受控有效缴款记录的最后日期；只有一条有效记录时，付款参考号必须逐字一致。
- 至少一份缴款证明或外部受控档案正式证据已经验证，且当前指纹未变化。

界面分别显示缴款成功、冲正、退库和有效净额。净额仅用于期间勾稽，不会把不同法律含义的记录合并成一条付款。

## 封存与完整性

申报快照包括公司、档案、期间、申报编码、适用义务及依据、截止日及依据、勾稽结果、标准化申报记录、提交日期和参考号，以及已验证正式证据指纹。

缴款快照包括申报档案、勾稽结果、全部受控缴款记录及状态、四类金额展示、付款日期和参考号，以及已验证缴款证据指纹。

两份快照分别保存 SHA-256 和封存时间，并由受控状态动作写入；客户端上下文无法伪造内部写入标记。后续范围、来源校验和、义务、正式证据或登记字段变化会显示完整性异常。新成功勾稽批次只把历史档案标记为“来源已被新批次替代”，不会改写原封存快照。

## 原生用户体验

- 增值税四方勾稽表单新增“申报缴款档案”按钮；已有档案时直接打开，没有档案时打开预填公司、期间、义务和受控申报结果的新建表单。
- 通用申报表单保留原生状态栏、任务、证据和 chatter，并增加中国增值税来源、完整性告警、缴款方向分列和三个只读明细页。
- 申报列表增加可选来源与完整性列，搜索视图增加“中国增值税受控档案”筛选。
- 截止日、官方依据、义务适用性、回执和缴款证明均保持显式人工确认，不用隐藏自动化替代专业判断。

## 安全与回归

运行时测试覆盖：

- 不推断法定截止日。
- 义务未确认适用时阻断待提交。
- 未验证正式回执时阻断提交。
- 申报和缴款完整链封存及审计事件。
- 申报应纳与缴款净额不一致时阻断“全部已付款”。
- 勾稽校验和篡改检测。
- 来源被新批次替代后的历史快照状态。
- 跨公司勾稽来源拒绝。

发布验收结果：

- 定向增值税期间测试执行 43 个方法，Odoo 统计 45 项，结果为 `0 failed / 0 errors`。
- 空库全量新装执行 169 个运行时测试方法，Odoo 统计 191 项，结果为 `0 failed / 0 errors`。
- 从 `19.0.1.18.0` 升级到 `19.0.1.19.0` 时，Odoo 明确执行 `19.0.1.19.0` 后迁移脚本；升级后再次执行 169 个运行时测试方法，Odoo 统计 191 项，结果为 `0 failed / 0 errors`。
- 真实数据隔离副本升级前后均为 15,589 张会计凭证和 44,651 条会计分录；凭证数、分录数、借贷合计及两张核心账务表的逐行内容摘要完全一致。
- 本地与服务器验收副本的 75 个插件文件逐文件 SHA-256 一致；本地静态契约、31 个纯 Python 测试和全目录编译全部通过。
- 验收期间正式 `odoo19.service` 始终为 `active`，只有正式 Odoo 进程，登录入口返回正常的 HTTP 303 跳转。

## 当前边界

- 当前国家包仍没有真人专业签核后生效的中国税法规则。
- 候选义务初始化为待确认；用户必须治理官方来源并完成公司级适用性判断。
- 截止日来源和计算说明必须反映企业、税种、期间、节假日、延期和地方口径，系统不提供法律结论默认值。
- 标准化 JSON、勾稽结果和正式证据用于受控内部档案，不替代税务机关系统中的申报表、回执或完税凭证原件。
