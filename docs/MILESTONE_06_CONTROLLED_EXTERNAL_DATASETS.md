# 里程碑 06：受控外部数据集

## 目标

为中国财税合规建立独立于 Odoo 会计账簿的外部数据入口，受控登记企业依法取得的电子发票与电子凭证、增值税申报、税款缴纳、个人所得税扣缴、银行证据和其他监管数据。

本里程碑只解决来源、范围、原件、真实性状态、文件完整性、复核和版本追溯，不宣称已经完成电子发票解析、账票税款勾稽或税法判断。

## 官方设计依据

- [财政部电子凭证会计数据标准通知](https://www.mof.gov.cn/jrttts/202505/t20250521_3964264.htm)
- [财政部电子凭证会计数据标准下载页](https://kjs.mof.gov.cn/zt/kuaijixinxihuajianshe/dzpzkjsjbzshsd/sjbz/202505/t20250519_3964020.htm)
- [电子凭证会计数据标准应用指南 PDF](https://kjs.mof.gov.cn/zt/kuaijixinxihuajianshe/dzpzkjsjbzshsd/czznhjswd/202505/P020250519337890192554.pdf)

应用指南把电子凭证处理区分为接收、验签或真实性验证、解析、报销入账和归档，并要求保持原始凭证与会计凭证之间的关联。本模型据此把“内部封存”和“真实性验证”设计为两个独立控制，不允许用上传文件或内部复核替代真实性验证结论。

## 数据模型

模型：`sudo.cn.external.dataset`

核心信息：

- 公司合规档案、数据集类型和覆盖期间。
- 完整、部分或抽样覆盖声明，以及范围与限制说明。
- 取得渠道、来源系统、批次引用、生成时间和数据格式。
- 依法取得或授权依据、敏感数据标记和数据保护说明。
- 源文件声明记录数、币种、价税合计和税额。
- 系统内保存的非空二进制源文件。
- 真实性验证状态、工具或方法、结果引用和验证证据。
- 采集人、复核封存人、SHA-256 校验和和完整性状态。
- 原版本、替代版本和不可改写的版本链。

## 生命周期

1. `待完善`：管理员录入来源、覆盖范围和附件。
2. `已封存`：字段完整并由另一名管理员复核；单人测试场景必须填写不少于 20 字的例外理由并进入审计轨迹。
3. `已替代`：新的替代版本完成封存后，原版本自动转为已替代。

已封存和已替代数据集不能修改或删除。发现错误时必须创建替代版本；原数据、校验和和审计事件继续保留。

## 控制门禁

- 只允许关联中国合规档案，并受 Odoo 允许公司规则隔离。
- 普通合规用户只读，合规管理员才能维护和封存。
- 创建接口不能伪造采集人、封存状态、封存人或校验和。
- 封存要求来源、授权、范围、记录数和非空源文件齐全。
- 结构化电子凭证原件必须留存受控工具通过结果、结果引用和验证证据；当前模型只治理该结果，不自行执行或认可密码学验签。
- 包含个人或敏感数据时必须记录访问、脱敏、授权或保存控制。
- 校验和包含受控元数据及全部源文件、验证证据的 SHA-256；附件内容变化会显示完整性异常。
- 审计事件只记录控制状态、记录标识和摘要哈希，不写入附件正文或来源引用。

## 原生界面

- `合规 -> 合规管理 -> 外部监管数据` 提供列表、搜索和表单。
- 中国合规档案增加“外部监管数据”页签。
- 列表直接显示真实性、复核控制、完整性和生命周期状态。
- 真实性失败、封存后变化、单人例外和已替代版本使用明确提示。

## 验证范围

新增运行时测试覆盖：

- 伪造状态和采集人被重置。
- 不完整、空附件和敏感数据控制缺失时不能封存。
- 独立复核、单人例外和审计事件。
- 结构化电子凭证真实性验证门禁。
- 封存后不可改删和附件篡改检测。
- 同类型、同档案替代版本链。
- 中国档案限制、普通用户只读和多公司隔离。

静态校验已经覆盖 Python、XML、清单版本、能力声明、升级迁移、菜单、ACL 和公司记录规则。由于共享底座仍由新加坡开发会话升级，本里程碑尚未在 Odoo 运行时数据库安装或升级验证。

## 下一步

1. 基于财政部电子发票 XBRL 标准建立规范化发票头、行、税额和原始凭证标识模型。
2. 使用官方或经验证的工具链执行验签和解析，不手写密码学验签逻辑。
3. 建立原始凭证与 Odoo 会计凭证的多对多关联。
4. 建立账、票、申报和缴税数据的期间覆盖与差异模型。
5. 只有在运行时测试和专业复核完成后，才将受控数据用于正式规则。
