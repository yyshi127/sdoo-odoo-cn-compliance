# M31 中国辖区治理与地方规则适用范围

交付版本：`sudo_country_pack_cn 19.0.1.28.0`。

## 1. 目标

M31 在已有中国合规包的来源治理、规则版本、评估和正式报告能力之上，补齐“中国地方规则适用性”的基础治理层。它解决的问题不是直接新增一批地方税收规则，而是先把地方规则能否安全进入规则引擎所需的治理对象、证据、冻结快照和发布门禁建立起来。

本阶段回答四个问题：

1. 一个地方辖区版本是否有官方依据、独立复核、有效期和完整性校验。
2. 一家公司在某个日期、税种或业务域下，是否有可审计证据证明其适用某个地方辖区。
3. 一条中国规则版本如果声明只适用于地方辖区，发布前是否能证明辖区有效且未被篡改。
4. 评估运行时，地方规则为什么被选中、排除或阻断，是否能形成冻结快照，避免事后解释漂移。

## 2. 主要新增能力

### 2.1 受控辖区版本

新增模型：`sudo.cn.jurisdiction.version`。

它用于维护中国合规规则依赖的行政、税务或特殊适用区域版本。每个辖区版本包含编码、名称、层级、父级、有效期、官方来源、适用边界说明、作者、独立复核人、状态和 SHA-256 校验和。

状态流转为：

`draft -> pending_review -> approved -> active -> retired`

关键门禁：

- 创建时不能伪造审批状态、审批人或校验和。
- 审批人必须具备规则审批权限。
- 编制人与审批人不能是同一用户。
- 生效前必须有已批准且快照完整的官方来源。
- 父级辖区必须有效，且有效期覆盖子级。
- 生效后的业务字段不可直接修改。
- 官方来源快照或父级发生完整性异常时，辖区完整性显示为异常。

### 2.2 公司适用辖区快照

新增模型：`sudo.cn.profile.jurisdiction`。

它用于记录某个合规档案在指定税种或合规域下适用哪个中国辖区。记录包含公司、档案、辖区、适用域、角色、有效期、证据来源类型、证据日期、证据编号、附件、边界说明、核实人、核实时间和校验和。

关键门禁：

- 适用辖区必须是有效且完整的中国辖区版本。
- 证据字段和附件不完整时不能核实。
- 核实后冻结证据附件哈希、辖区校验和与适用性校验和。
- 证据附件或辖区版本被篡改后，完整性会变为异常。
- 同一公司、同一档案、同一适用域和角色下，不允许重叠的已核实适用期。
- 记录规则按 `company_id in company_ids` 隔离多公司数据。

### 2.3 规则版本的地方适用范围

扩展模型：`sudo.compliance.rule.version`。

新增字段：

- `cn_jurisdiction_ids`
- `cn_jurisdiction_domain`
- `cn_jurisdiction_scope_state`
- `cn_jurisdiction_scope_blockers`

设计边界：

- 空辖区范围表示全国规则，保持既有规则校验和和选择行为不变。
- 非空辖区范围表示地方适用规则，规则校验和会包含辖区编码、版本、层级、有效期和辖区校验和。
- 地方规则发布前必须确认所有辖区已生效、完整性正常，并覆盖规则有效期。
- 地方范围变更会重置规则的测试、专业签核和技术审批状态，避免旧签核覆盖新适用范围。
- 如果地方范围无效，规则发布状态进入 `jurisdiction_governance`，不能作为正式可发布规则处理。

### 2.4 评估冻结快照

扩展模型：`sudo.compliance.assessment`。

新增字段：

- `cn_jurisdiction_coverage_state`
- `cn_jurisdiction_assignment_count`
- `cn_jurisdiction_scoped_rule_count`
- `cn_jurisdiction_selected_rule_count`
- `cn_jurisdiction_excluded_rule_count`
- `cn_jurisdiction_blocked_rule_count`
- `cn_jurisdiction_scope_snapshot_json`
- `cn_jurisdiction_scope_checksum`
- `cn_jurisdiction_scope_integrity_state`
- `cn_jurisdiction_coverage_message`

评估运行时会冻结：

- 本次评估日期下有效的公司辖区适用记录。
- 被选中的地方规则。
- 被排除的地方规则及原因。
- 被阻断的地方规则及原因。
- 所有参与判断的辖区和适用证据校验和。

如果地方规则存在但企业缺少有效适用辖区证据，评估结论会标记为 `incomplete`，不是“无风险”。如果辖区或证据完整性异常，评估结论标记为 `integrity_error`，并限制正式报告给出清晰结论。

## 3. 原生 Odoo 集成

新增和扩展的界面全部采用 Odoo 原生菜单、列表、表单、搜索、状态栏、badge、notebook 和 record rule：

- 合规配置菜单新增“中国受控辖区”。
- 合规档案/管理菜单新增“辖区适用快照”。
- 合规档案表单新增“中国适用辖区”页签。
- 规则版本表单新增“中国地方适用范围”页签。
- 评估表单新增“地方规则范围”页签和覆盖状态提示。

注意：M31 仍属于规则治理和配置层能力，不是最终面向老板或财务负责人的中国合规总览页面。当前应用外壳仍复用 `sudo_global_finance` 底座，因此整体导航和新加坡包相似是预期现象。中国差异体现在 `sudo_country_pack_cn` 的规则、税种数据、勾稽、申报档案和本次新增的辖区治理能力。

## 4. 安全与数据边界

- 包内不预置任何 active 中国辖区。
- 包内不预置任何地方适用规则。
- 现有 11 条中国规则候选继续保持 draft，不自动生效。
- 地方规则不因演示或安装自动启用。
- M31 不修改会计凭证、会计分录、业务单据、发票、申报记录或缴款记录。
- M31 不改变新加坡包、全局底座正式代码或主 Odoo 服务。

## 7. 已知边界与下一步

M31 不代表中国合规插件最终完成。它只是补齐地方规则进入规则引擎前的治理能力。

下一步应优先推进：

1. 面向查看体验的“中国合规总览、风险中心、整改跟踪、报告中心”页面，让风险等级、期间、影响金额、责任人、证据缺口和下一步动作一目了然。
2. 将已有增值税、企业所得税、个人所得税、发票和缴款归集能力串入统一评估工作台。
3. 治理首批正式中国规则：官方来源快照、专业签核、测试用例、技术审批和正式激活。
4. 做全国规则与地方规则混合场景的端到端演示：档案 -> 适用辖区 -> 数据导入 -> 扫描 -> 风险 -> 整改 -> 复扫 -> 报告。
5. 在真实数据副本上继续验证不改账、不误报“无风险”、不绕过缺证限制。
