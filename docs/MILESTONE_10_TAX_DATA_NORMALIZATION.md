# 里程碑 10：增值税申报与税款缴纳数据标准化

## 目标

为增值税申报数据和税款缴纳数据建立严格、可版本化、可审计的内部标准化契约，形成不可随意改写的申报台账与缴税台账，为后续“账务、发票、申报、缴税”期间勾稽提供稳定输入。

本里程碑不连接税务机关，不自动提交申报，不发起扣款，也不根据导入结果直接形成税法或合规结论。

## 交付范围

- 中国国家包版本升级为 `19.0.1.8.0`。
- 新增严格 JSON 契约 `sdoo.cn.tax-data.v1`，支持 `vat_filing` 和 `tax_payment` 两类数据。
- 新增受控导入运行、增值税申报记录、申报行和税款缴纳记录。
- 在受控外部数据集表单提供导入入口、结果计数和当前成功版本入口。
- 提供“增值税申报台账”“税款缴纳台账”“申报缴税导入运行”原生 Odoo 菜单。
- 新增 `19.0.1.8.0` 升级迁移，安全更新国家包运行态元数据。

## 输入契约

输入必须为 UTF-8 JSON，可包含 UTF-8 BOM，并满足以下要求：

- 顶层 `schema` 必须精确等于 `sdoo.cn.tax-data.v1`。
- `dataset_type` 必须与受控数据集类型一致。
- 必须声明源格式名称、源格式版本、记录数量和非空记录数组。
- 每个受控数据集必须且只能包含一份标准化 JSON 源文件。
- 声明数量必须同时与 JSON 记录数、受控数据集声明记录数一致。
- 顶层、记录和申报行只允许白名单字段，未知字段直接拒绝。
- 任意层级出现重复 JSON 字段直接拒绝。
- `NaN`、`Infinity` 等非标准 JSON 常量直接拒绝。
- 每条记录的 `source_record_key` 必须唯一。
- 同一申报记录中的 `line_code` 必须唯一。
- 单个文件最大 20 MB、最多 10,000 条记录、单份申报最多 500 行。

格式样例：

- [增值税申报样例](samples/cn_vat_filing_contract_v1.example.json)
- [税款缴纳样例](samples/cn_tax_payment_contract_v1.example.json)

样例中的企业名称、统一社会信用代码、申报编号和缴款编号仅用于说明格式，实际导入前必须替换为受控来源中的真实值。

## 零值与缺失

金额字段同时保存“是否提供”和“金额值”。例如：

- 提供 `"tax_payable_amount": "0.00"` 表示来源明确给出应纳税额为零。
- 完全不提供 `tax_payable_amount` 表示来源没有该字段。
- 空字符串、非法日期、非法币种或非法金额不会被静默转换为零。

申报台账保留销售额、销项税额、进项税额、进项税额转出、上期留抵、应纳税额、退税额和期末留抵的提供状态。缴税台账保留缴款总额、本金、利息和滞纳金的提供状态。

## 数据质量控制

导入过程显式记录数据质量问题，包括：

- 纳税人识别号与当前 Odoo 公司不一致。
- 申报期间或税款所属期超出受控数据集声明范围。
- 缺少应纳税额或缴款金额。
- 总金额与本金、利息、滞纳金合计不一致。
- 申报状态、缴款状态、币种、日期或金额无法识别。
- 付款账号不是脱敏值。

未脱敏付款账号不会进入标准化台账，只保留 `UNMASKED_PAYER_ACCOUNT` 问题代码。合法脱敏值也会统一转换为只含星号和最后不超过四位数字的形式，系统不原样保存完整银行账号或其他账号文本。

## 版本与审计

- 导入前要求数据集已封存、完整性验证通过、附件哈希一致且由合规管理员执行。
- 每次运行保存数据集封存哈希、原始附件哈希、契约哈希、映射版本和规范化输出哈希。
- 记录哈希只使用稳定问题代码与严重级别，不受登录用户界面语言影响。
- 标准化记录和申报行不可手工创建、任意修改、复制或删除。
- 失败重跑不会替代上一份成功结果。
- 新成功结果只替代同一受控数据集的上一成功结果，并保留完整版本链。
- 开始、失败、成功和替代均写入合规审计事件。

## 权限与多公司

- 普通合规用户只有只读权限。
- 合规管理员通过受控向导启动导入，但不能删除审计记录。
- 导入运行、申报记录、申报行和缴税记录均按 Odoo 允许公司隔离。
- 普通用户无法通过 ORM 直接伪造或修改标准化结果。

## 自动化校验

已完成并通过 12 个不依赖 Odoo 的契约测试，覆盖合法申报、合法缴税、UTF-8 BOM、类型匹配、未知字段、重复 JSON 字段、数量不一致、重复业务键、重复申报行、非法 JSON 和非字节输入。

已编写 12 个 Odoo 运行时测试，覆盖受控创建、封存与格式门禁、零值保留、灵活申报行、主体不一致、期间越界、脱敏账号、声明数量不一致、失败重跑、成功替代、结果不可改写和多公司隔离。

`tools/validate_addon.py` 已将模型导入、契约服务、关键质量代码、哈希字段、审计事件、ACL、公司规则、视图、菜单和最低运行时测试数量纳入持续门禁。

## 未完成项

- 12 个 Odoo 运行时测试尚未在目标 Odoo 19 数据库执行。
- 尚未验证真实税务软件导出格式；当前入口只接受内部受控标准化 JSON。
- 尚未实现税局申报接口、银税缴款接口或任何官方导出格式的专用适配器。
- 尚未完成账务、发票、申报和缴税之间的期间勾稽及差异整改闭环。
- 正式中国财税规则仍需官方原文快照、有效期、测试、独立审批和中国财税专业签核。

因此，本里程碑证明申报与缴税数据的内部标准化及审计边界已经形成代码基线，不代表整个中国财税合规包已经完成，也不构成申报成功、缴款成功或税务合规结论。
