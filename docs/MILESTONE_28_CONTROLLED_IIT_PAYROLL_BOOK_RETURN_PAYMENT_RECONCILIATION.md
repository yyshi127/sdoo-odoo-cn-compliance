# M28 中国个人所得税工资、账簿、申报与缴退税受控勾稽

交付版本：`sudo_country_pack_cn 19.0.1.25.0`。

## 1. 目标与设计决策

M28 在 M27 个人所得税扣缴申报标准化台账之上，建立企业级工资汇总、Odoo 会计账簿、个税扣缴申报和缴退税来源之间的可解释勾稽。

本里程碑没有在缺少可靠工资模块时从员工、科目名称或凭证摘要推测工资，也没有保存自然人身份字段。系统只接受企业依法取得、经过封存的期间汇总，使用人工配置并经过证据核验的会计取数口径，逐层判断数据是否可比较。

结果只可能是：

- `数据不足`：缺少口径、工资、申报、缴退税或来源控制，不能形成金额一致或不一致结论；
- `存在待复核差异`：来源可比较，但一个或多个金额或人数不一致；
- `当前口径算术一致`：可比较项目在当前口径下无差异，仍不是个税合规结论。

数据字段和隐私边界继续参考以下税务机关公开材料：

- [《个人所得税基础信息表（A 表）》](https://shanghai.chinatax.gov.cn/bsfw/xzzx/bgxz/sbzsl/202402/t470788.html)

这些材料只是产品数据语义的公开设计参考，不是已经进入本系统的受控原文快照，也没有完成来源独立审批、规则测试或真人中国财税专业签核。M28 没有发布法定税率、扣除、截止日、居民身份、所得项目或税额计算规则。

## 3. 企业级工资汇总契约

`sdoo.cn.tax-data.v1` 新增 `payroll_summary` 数据集类型，保存：

- 精确期间、币种、薪资频次、状态、批次引用和确认时间；
- 汇总人数、工资薪酬收入、免税收入；
- 个人承担社会保险费、住房公积金、其他税前扣除；
- 实发金额和代扣个人所得税。

人数和金额使用独立 `has_*` 字段区分“来源明确为零”和“来源缺失”。缺少人数、收入总额或代扣个税会形成数据错误；草稿、取消或未知状态不能进入最终勾稽。

该契约只接受企业级汇总，不定义姓名、证件、手机号、地址、银行卡、员工编号或人员明细。未知身份字段会被白名单拒绝。示例见 `docs/samples/cn_payroll_summary_contract_v1.example.json`。

工资汇总原始数据集、导入运行和标准化记录只允许当前公司的合规管理员访问；普通合规用户只能查看勾稽结果中的必要聚合数量和金额。

## 4. 已核验个税账务口径

新增按合规档案和有效期管理的个税账务口径。每份口径必须明确配置：

- 工资薪酬成本科目；
- 应付职工薪酬科目；
- 应交个人所得税科目；
- 工资汇总 `source_schema` 及版本；
- 个税申报 `source_schema` 及版本；
- 来源应补退税额的正负号解释；
- 取数范围、排除、时点和限制；
- 系统内非空工作底稿。

系统不按科目代码、名称或凭证摘要自动填充口径。科目类型与角色不一致时必须记录受控例外；编制人与核验人为同一人时必须记录不少于 20 字的例外理由。

核验时冻结口径、科目、账户元数据、说明和附件 SHA-256。同一档案的已核验有效期不能重叠。已经进入勾稽快照的口径不能撤销核验、修改或删除，后续变化必须新建口径。

## 5. 五层数据充分性

每次运行分别显示：

1. 账务口径；
2. Odoo 已过账账簿；
3. 受控工资汇总；
4. 受控个税扣缴申报；
5. 受控缴退税记录。

来源必须与档案、公司、币种和期间精确匹配。工资与申报来源结构及版本必须和已核验口径一致。部分覆盖、封存完整性异常、真实性验证失败、多份当前结果、非最终状态、字段质量错误或本金缺失都会阻断比较。

“没有记录”不等于零业务、无需申报、无需缴款或已经合规，因此缺失来源固定返回数据不足。

## 6. 勾稽项目

在所有对应来源可比较时，系统分别执行：

- Odoo 工资薪酬成本净发生额与工资汇总收入总额；
- 应付职工薪酬贷方发生额与工资汇总收入总额；
- 工资汇总人数与个税申报人数；
- 个税申报收入与工资汇总收入；
- 个税申报税额与工资汇总代扣个税；
- 应交个人所得税贷方发生额与工资汇总代扣个税；
- 受控缴款日期的应交个人所得税借方发生额与有效缴款本金；
- 按已核验符号解释的申报应补税额与有效缴款本金；
- 按已核验符号解释的申报应退税额与已退库本金。

缴款经常发生在税款所属期之后，因此账簿结算不是限制在申报所属期内，而是使用当前期间受控缴退税来源所列的实际缴款日期读取应交个税科目。这个日期口径可能仍包含合并缴款、冲正或其他所属期事项，页面会保留来源日期、账簿摘要和工作底稿限制，差异必须人工复核。

人数差异使用独立整数栏位，不按人民币显示。所有金额差异保留左右口径、原值、差额、说明和下一步建议，不把多项差异相加为税务影响额。

## 7. 审计、队列与不可改写性

每次运行保存：

- 已核验会计口径完整 JSON 快照和 SHA-256；
- 已过账期间分录、缴款日期分录的逐行摘要及 SHA-256；
- 工资汇总、个税申报和缴退税来源快照及 SHA-256；
- 问题清单、比较金额、人数、状态和完整结果 SHA-256。

批次和问题只能由进程内受控标记创建，完成后不可修改、复制或删除。新成功批次只会把旧成功批次标记为已替代，不会改写旧快照。

后台队列使用数据库行锁和 `FOR UPDATE SKIP LOCKED`。同一档案和期间的待处理或处理中批次具有数据库级唯一索引，避免并发重复执行。

## 8. 权限与原生查看体验

- 合规管理员配置和核验账务口径、导入工资与个税来源、发起勾稽；
- 普通合规用户按允许公司只读查看聚合批次、差异和下一步建议；
- 工资汇总和个税申报关联字段、打开动作及源台账均只向合规管理员开放；
- 所有口径、批次、问题和敏感来源均受多公司记录规则隔离。

页面继续使用 Odoo 原生菜单、搜索、列表、徽章、状态栏、表单、页签、统计按钮和公司上下文。运行表单把五层数据状态、关键金额、差异矩阵、问题与下一步、来源及审计分区展示；数据不足、差异、算术一致和完整性异常使用不同原生提示状态。

## 9. 升级策略

版本 `19.0.1.25.0` 使用增量后迁移更新国家包版本和能力元数据。新增模型、字段、ACL、记录规则、队列和视图由 Odoo 模块升级创建，不修改会计凭证、会计分录、既有标准化来源、历史勾稽或规则签核状态。

能力清单新增：

- `payroll_summary_normalization: true`

能力存在不代表已经具有工资计算、个税计算、税务机关接口、自动申报、自动扣款、正式个税规则或合规结论。

## 11. 明确未交付内容与下一步

M28 不交付：

- 工资单、工资计算或逐人薪税计算；
- 居民身份、所得项目、扣除、税率、优惠或应扣税额判定；
- 税务机关接口、自动申报、自动缴款或官方导出格式适配承诺；
- 法定截止日和企业适用性自动判断；
- 已治理、已独立审批且经真人中国财税专业签核的个税规则；
- 申报正确、足额缴税、可退税或个人所得税合规结论。

下一里程碑应把 M28 的精确期间、来源状态、差异和完整性事实受控桥接到规则扫描、风险、整改、证据和验证复扫闭环，并设计个税申报与缴退税正式档案。候选规则仍必须经过官方原文快照、有效期、测试、独立审批和真人中国财税专业签核后才能发布。
