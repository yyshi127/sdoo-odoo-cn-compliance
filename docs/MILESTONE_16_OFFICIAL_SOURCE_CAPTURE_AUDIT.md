# 里程碑 16：官方来源技术采集审计

## 目标

在独立来源复核和中国财税专业签核前，验证七项候选官方来源能否通过生产同等 TLS 校验、HTTP 状态、内容类型和大小限制形成受控快照。技术可采集不等于内容已完成法律复核。

交付版本：`sudo_country_pack_cn 19.0.1.14.0`。

## 发现的问题

首次从 Odoo 服务器网络环境审计七个候选地址时：

- 全国人大法律法规数据库《会计法》PDF 地址因服务器证书过期而无法通过 TLS 验证。
- 财政部《会计档案管理办法》原地址返回 HTTP `502`，响应不是可接受的官方正文。
- 其余五项候选地址均返回 HTTP `200` 和可保存的 HTML。

系统没有使用 `curl -k`、关闭证书校验或保存错误页来绕过问题。

## 升级保护

由于候选来源安装数据使用 `noupdate`，`19.0.1.14.0` 提供显式迁移。迁移只有同时满足以下条件才替换旧地址：

1. 来源仍为草稿。
2. 尚无快照附件。
3. 尚无内容 SHA-256。
4. 当前地址仍精确等于插件原来的旧地址。

用户已修改、已采集、待复核、有效、过期或已替代的来源均不会被静默改写。成功迁移会写入审计事件并记录旧地址和新地址。

## 安装数据边界

- 安装包只登记候选元数据和经过技术审计的官方 URL。
- 安装包不预置网页正文、快照附件、内容哈希、复核人或有效状态。
- 官方网页必须在目标数据库中由规则维护人员通过受控采集动作获取。
- 采集成功后仍需不同人员逐页核对正文、版本、发布机关、发布日期、适用范围和后续修改，并完成来源审批。
- 来源有效仍不等于规则可发布；规则测试、企业适用性、真人专业签核和独立技术审批继续作为发布门禁。

## 验收顺序

1. 空库安装确认七项候选仍为草稿且地址精确匹配审计清单。
2. 从 `19.0.1.13.0` 升级，确认仅两个未治理旧地址被安全替换。
3. 在隔离真实数据副本调用 Odoo 原生官方网页采集动作。
4. 核对七份附件的内容类型、字节数、最终 URL、HTTP 状态和 SHA-256。
5. 保持来源为草稿或待独立复核，不执行自动批准。

空库新装和从 `19.0.1.13.0` 升级均通过 `129` 个运行时测试方法，Odoo 测试统计为 `147` 项，结果 `0 failed / 0 errors`。
