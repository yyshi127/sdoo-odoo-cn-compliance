# 里程碑 07：电子发票规范化与解析契约

## 目标

建立电子发票从受控源文件到规范化只读台账的审计边界，为后续账、票、申报和缴税勾稽提供稳定数据结构。本里程碑交付解析运行契约和规范化结果模型，不交付或宣称已经运行财政部 XBRL 解析器。

## 官方结构依据

财政部电子凭证会计数据标准及实例显示：电子发票包含发票号码、销售方信息、不含税金额、税额、价税合计、开具或申请时间、会计主体信息等事实；一张电子发票可以包含多组会计凭证信息，每组会计凭证又包含多条借贷分录。

- [财政部电子凭证会计数据标准通知](https://www.mof.gov.cn/jrttts/202505/t20250521_3964264.htm)
- [财政部电子凭证会计数据标准下载页](https://kjs.mof.gov.cn/zt/kuaijixinxihuajianshe/dzpzkjsjbzshsd/sjbz/202505/t20250519_3964020.htm)
- [财政部应用指南 PDF](https://kjs.mof.gov.cn/zt/kuaijixinxihuajianshe/dzpzkjsjbzshsd/czznhjswd/202505/P020250519337890192554.pdf)

因此，本模块没有把电子发票和 Odoo 会计凭证设计成简单一对一关系。

## 模型边界

### `sudo.cn.external.parse.run`

- 绑定一份当前已封存、文件完整性正常的电子发票数据集。
- 固化输入附件、输入 SHA-256、数据集封存校验和。
- 固化解析器键、版本、发行包及分类标准命名空间、版本、来源和 SHA-256。
- 保存源事实数、规范化文档数、警告或错误数和输出校验和。
- 生命周期为解析中、成功、失败和已被新结果替代。
- 同一数据集同一时刻只能有一个解析中的运行。

### `sudo.cn.einvoice.document`

- 保存发票号码、开具时间、销售方、会计主体和币种。
- 分别记录金额是否提供，严格区分缺失和零值。
- 保存不含税金额、税额、价税合计及其一致性结果。
- 保存红字、入账、查验、支付、合同、银行回单和用途确认状态。
- 继承源数据覆盖范围、真实性验证和复核控制状态。
- 保存字段级问题清单、源事实摘要和规范化文档 SHA-256。

### 会计凭证引用和借贷分录

- `sudo.cn.einvoice.accounting.document` 保存会计凭证编号、入账日期、期间、摘要和借贷合计。
- `sudo.cn.einvoice.accounting.entry` 保存借贷方向、总账科目、明细科目和入账金额。
- 同一电子发票可以关联多张会计凭证信息。
- 规范化层保存源文件表达，不把科目名称直接猜测为 Odoo 科目或凭证。

## 受控执行

- 解析运行和全部规范化结果不能通过普通 ORM、导入或界面手工创建。
- 只有服务端受控解析契约持有的不可序列化标记可以创建结果。
- 源文件不是数据集附件、数据集未封存或文件完整性异常时不能开始解析。
- 解析进程必须回传实际读取文件的 SHA-256；与封存哈希不一致即失败。
- 解析器报告错误时不生成规范化文档。
- 规范化字段错误会被保留为异常文档，不被改写成正常数据。
- 失败重跑不替代上一份成功结果；新运行成功后才将旧成功结果标记为已替代。
- 解析运行、发票、会计凭证引用和分录均不可修改或删除。

## 数据质量

当前内部检查包括：

- 发票号码、销售方名称、销售方识别号、币种和价税合计是否提供。
- 不含税金额加税额是否等于价税合计。
- 会计主体名称和统一社会信用代码是否提供。
- 开具或申请时间是否有效。
- 会计期间是否为 `YYYY-MM`。
- 借贷方向、金额和总账科目是否可识别。
- 每组会计凭证借贷是否平衡。
- 是否提供会计凭证关联信息。

`字段校验正常` 不代表源文件真实性通过，也不代表发票可抵扣、可税前扣除、已正确申报或已完成账票匹配。

## 解析器技术决策

[Arelle 2.42.1](https://arelle.readthedocs.io/en/2.42.1/python_api/python_api.html) 提供受支持的 Python API、XBRL 模型查询和验证能力，并由 XBRL International 认证为验证处理器。其官方文档同时明确：Arelle 使用共享全局状态，同一进程内不能并发运行多个 Session。

因此后续适配器必须：

1. 作为可选 Odoo 子模块交付，不阻塞中国国家包基础能力安装。
2. 在隔离子进程中运行 Arelle，不在 Odoo 多线程请求进程中直接并发创建 Session。
3. 默认离线解析，使用经过来源治理和 SHA-256 封存的财政部分类标准包。
4. 设置执行超时、输入大小、解压路径和输出大小限制。
5. 只返回规范化 JSON、错误计数和日志摘要哈希，不把原始敏感数据写入日志。
6. 在服务器 Python 版本和财政部实例包上完成兼容性测试后再锁定 Arelle 版本。

当前 `einvoice_xbrl_parser` 能力明确保持 `False`，不得把模型契约误报为解析器已交付。

## 原生界面

- `合规 -> 合规管理 -> 电子发票台账`：默认显示当前有效解析结果。
- `合规 -> 合规管理 -> 数据解析记录`：查看成功、失败和已替代运行。
- 外部数据集表单增加解析运行数和规范化发票数入口。
- 列表直接显示字段质量、源数据覆盖范围、真实性验证和当前结果状态。

## 验证状态

新增运行时测试覆盖受控创建门禁、封存和哈希门禁、规范化层级、金额与借贷校验、失败重跑、成功替代、并发运行、多公司隔离和只读不可改写。静态 Python、XML、版本、迁移、ACL、记录规则和能力声明已纳入仓库门禁。

共享底座仍由新加坡开发会话升级，因此本里程碑尚未在 Odoo 运行时安装或升级，也没有执行 Arelle 解析。
