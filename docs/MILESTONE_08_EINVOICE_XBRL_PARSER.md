# 里程碑 08：电子发票 XBRL 隔离解析器

## 目标

把里程碑 07 的只读规范化契约接入可治理、可复现、可审计的财政部电子发票 XBRL 解析能力，同时确保官方分类标准、企业源文件和解析结果都不能绕过受控流程。

## 交付范围

- 新增可选 Odoo 插件 `sudo_country_pack_cn_einvoice_xbrl`，基础国家包不强制安装 Arelle。
- 固定并校验 `arelle-release==2.42.1`，解析版本写入每次运行记录。
- 建立财政部分类标准包登记、独立复核、SHA-256 封存、完整性检查和不可改写替代版本链。
- 安全检查 ZIP 路径穿越、符号链接、加密、大小、压缩比、重复路径、DTD、无效 XSD、入口文件和事实命名空间。
- 后台队列使用 `FOR UPDATE SKIP LOCKED` 领取任务，解析在受限临时目录和独立 Python 子进程中离线执行。
- 子进程再次校验源文件和分类标准原始哈希，只接受有界 JSON 结果。
- Arelle 错误会使解析失败且不生成当前结果；失败重试不替代上一份成功台账。
- 成功结果保留发票关键字段、会计单据和借贷分录，并记录事实摘要与解析日志摘要。
- 可选插件保护运行态能力标记，基础中国包后续升级不会把已安装解析器误标为未启用；卸载钩子仍会受控关闭该标记。

## 官方分类标准兼容治理

本次取得的财政部电子发票分类标准 ZIP 原始 SHA-256 为：

`EB75E173C1315742302DF5EDF74CF9E5AED51C2733B820A3236D9CFBB7F0BD8B`

分类标准中的两个 `link:roleType@roleURI` 值含尾部空格，而实例与引用使用无空格 URI。未经处理时，Arelle 会报告角色引用相关校验错误。实现采用以下受控方式：

1. 封存时扫描全部 XSD 并记录问题数量。
2. 严格模式检测到问题即拒绝封存或解析。
3. 只有显式选择 `trim_role_uri_whitespace_v1` 并填写复核说明后，才允许在隔离工作副本中修剪 `roleURI` 两端空白。
4. 原始 ZIP 和原始哈希不改写，工作副本不落入 Odoo 附件或仓库。
5. 工作进程校验实际修正数必须等于封存记录，并返回确定性的工作副本树哈希。
6. 若后续官方包已修正该问题，旧兼容方案会因“不适用”而拒绝执行，必须重新按严格模式封存。

当前官方包经 2 处受控修正后的工作副本树 SHA-256 为：

`7b14a6c4738f50e78508e152980ad9aec05e5b622693c9d632d42aaebece5b60`

该哈希是按相对路径及每个展开文件内容确定性计算的审计指纹，不替代原始 ZIP 哈希。
