# 里程碑 15：中国规则性质与发布就绪治理

## 目标

在首批中国规则进入官方来源治理和专业签核前，先建立不可绕过的结论边界，避免把数据缺失、流程未完成或内部控制异常误写成违法、少缴税或申报错误。

交付版本：`sudo_country_pack_cn 19.0.1.13.0`。

## 规则性质

中国规则主档必须从以下五类中明确选择一种：

| 规则性质 | 适用边界 |
| --- | --- |
| 法定义务 | 表达经正式来源、适用性和专业签核确认的法定义务 |
| 税额计算 | 表达经版本化参数和测试验证的税额计算或调整规则 |
| 申报与缴款时限 | 表达经正式来源确认的申报、缴纳或资料报送时限 |
| 内部控制 | 识别账务、凭证、复核或流程控制问题，不直接形成违法结论 |
| 数据准备度 | 识别数据缺失、范围不足、勾稽阻断或质量问题，不直接形成税法结论 |

规则一旦存在版本，规则性质即被冻结。业务性质需要改变时必须创建新的规则编码，避免历史评估结果被重新解释。

## 发布就绪状态

每个中国规则版本实时汇总以下治理条件：

1. 规则性质已经明确。
2. 内部控制和数据准备度规则强制要求人工复核。
3. 至少一项官方来源具有可发布原文快照、SHA-256、有效状态和未过期复核日。
4. 至少一个规则测试用例存在且全部通过。
5. 中国财税专业人员完成与当前规则内容哈希绑定的独立签核。
6. 技术复核、批准和发布状态符合通用规则生命周期。

界面显示“规则性质待明确、复核边界待设置、官方来源待治理、规则测试待通过、专业签核待完成、可提交技术复核、技术复核中、可发布生效、已正式生效、生效后需关注、已退役”等状态，并同时列出全部阻断事项。

官方来源即使仍标记为有效，只要超过下次复核日期，中国规则发布门禁也会直接阻断批准或生效，避免依赖定时任务延迟造成时效漏洞。

## 审计与结果边界

- 中国规则性质进入规则版本业务校验和及专业签核哈希。
- 风险结果保存可检索、可分组的规则性质标签。
- 数据准备度和内部控制结果在风险列表及详情页明确显示结论边界。
- 规则配置、规则版本和风险结果继续使用 Odoo 原生列表、表单、筛选、权限和多公司上下文。
- 升级迁移仅为此前没有分类字段的七条受控草案回填性质，不改写用户已确定的分类。

## 当前发布阻断

七项官方来源目前仍是候选草稿，没有原文快照、内容哈希和独立复核；七条规则也没有真实中国财税专业签核。因此当前正确状态是“官方来源待治理”，不得激活，更不得在报告中宣称已经完成中国税法合规判断。

## 验收结果

- 本地静态校验、XML/Python 语法和 29 项数据契约测试通过。
- 隔离空库新装执行 129 个运行时测试方法，Odoo 统计 147 项，结果为 `0 failed / 0 errors`，日志无 `ERROR`、`CRITICAL` 或 `Traceback`。
- 从 `19.0.1.12.0` 基线升级到 `19.0.1.13.0` 后执行相同全量测试，结果仍为 `0 failed / 0 errors`；七条旧草案准确回填为五条数据准备度和两条内部控制，且全部保持草稿。
- `odoo_2601` 隔离真实数据副本升级后仍有 15,589 张会计凭证和 44,651 条会计分录。
- 真实数据副本中原有增值税勾稽批次仍为 `succeeded / insufficient_data`，发票销项税额 `5.18`、会计口径和结果 SHA-256 均未变化。
- 七项官方来源仍全部保持草稿，系统没有自动批准来源、激活规则或伪造专业签核。

## 后续顺序

1. 逐项留存官方原文或官方网页快照并生成 SHA-256。
2. 由不同人员完成来源独立复核并设置下一次复核日期。
3. 运行规则正反案例并冻结测试结果。
4. 由具有可验证中国财税资质的人员记录签核证据和专业意见。
5. 由独立技术审批人批准并发布首批规则。
6. 在隔离真实数据副本执行规则扫描，验证风险、整改、证据、复扫和报告边界。
