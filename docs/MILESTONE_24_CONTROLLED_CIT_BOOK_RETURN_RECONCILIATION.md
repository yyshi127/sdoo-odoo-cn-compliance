# 里程碑 24：受控企业所得税账税与缴退税勾稽

## 目标

在里程碑 23 的企业所得税来源申报台账之上，建立可核验的 Odoo 会计利润取数口径，并把同一精确期间的账簿、来源申报、缴款、冲正和退库事实连接为不可改写的勾稽快照。

交付版本：`sudo_country_pack_cn 19.0.1.21.0`。

本里程碑回答的是“受控来源金额能否比较、算术是否一致、哪些资料仍需复核”，不判断税前扣除、纳税调整合法性、税率、优惠、亏损弥补、关联交易、跨境事项或企业所得税申报是否合法。差异只形成复核事项；金额一致也不构成税务合规结论。

## 会计利润口径

系统为每个中国合规档案建立按有效期管理的“企业所得税会计利润口径”。一份口径覆盖当前公司全部有效损益科目，而不是要求用户逐科目建立分散配置：

- `income`、`income_other` 默认按贷方减借方形成利润增加额。
- `expense`、`expense_depreciation`、`expense_direct_cost` 默认按借方减贷方形成利润减少额。
- 会计利润等于利润增加额减利润减少额。
- 非标准方向必须逐科目记录不少于 20 个字符的例外理由。
- 核验前必须覆盖全部当前有效损益科目，并记录来源依据、口径说明和证据附件。
- 编制人与核验人原则上分离；同人核验必须记录受控例外理由。
- 核验后保存包含档案、期间、说明、附件以及科目代码、名称、类型和角色的 SHA-256。

已核验口径不可直接修改。若科目表新增或恢复有效损益科目、口径字段或证据发生变化，完整性检查会阻止新的勾稽，要求撤销核验、同步科目并重新形成工作底稿。

## 精确期间账税链

每次运行由用户明确选择中国合规档案、起止日期、来源申报期间类型和来源数据实际使用的所得税代码。系统不会猜测税种编码，也不会把季度、年度或重叠期间静默合并。

运行执行四项独立比较：

1. Odoo 已过账损益科目计算的会计利润，与来源申报中的会计利润比较。
2. 来源申报内部的“会计利润 + 纳税调增 - 纳税调减”，与来源应纳税所得额比较。
3. 来源应补所得税额，与缴款成功本金减已冲正本金比较。
4. 来源应退所得税额，与已退库本金比较。

应补和应退保持两个独立方向，不计算净额。利息和滞纳金单独披露，不会被当作税款本金。处理中或失败缴款不计入有效缴款；有效记录缺少本金时比较被阻断，不能用包含利息或滞纳金的总额替代。

## 数据充分性

以下情况形成阻断问题，结论固定为“数据不足”：

- 缺少覆盖期间的唯一已核验会计利润口径，或口径完整性失效。
- 口径没有覆盖当前全部有效损益科目。
- 当前期间没有已过账损益分录，无法证明会计利润为零。
- 缺少完全匹配期间和申报类型的唯一当前企业所得税申报。
- 申报来源存在质量、主体、币种、覆盖或完整性错误。
- 缺少覆盖当前所属期的唯一完整缴退税数据集。
- 缴退税状态、币种或本金字段不足以判断有效金额。

未过账损益分录、来源真实性尚未确认、单人复核例外和非生效缴款形成醒目的复核提示。缺失金额由独立 `has_*` 状态保存，不会静默补零。即使所有可比较金额一致，只要存在来源或结账限制，界面仍显示黄色限制提示。

## 状态与审计

运行采用原生 Odoo 后台队列，生命周期为待处理、处理中、成功、失败、已取消和已被替代。队列使用 `FOR UPDATE SKIP LOCKED` 防止并发重复处理，并限制单次账务、申报和缴退税记录规模。

每份成功结果冻结：

- 会计利润口径快照及 SHA-256。
- 已过账损益分录流式摘要、按科目汇总和 SHA-256。
- 唯一来源申报、导入运行、数据集封存指纹和 SHA-256。
- 缴款、冲正、退库、本金、利息、滞纳金及来源指纹和 SHA-256。
- 逐项差异、问题、限制、下一步建议和完整结果 SHA-256。

运行和问题不能手工创建、改写、复制或删除。失败运行不会替代上一份成功结果；新成功结果只把旧结果标记为已被替代，历史快照继续保留。

## 规则闭环

里程碑新增五项企业所得税勾稽事实：

- `cn.reconciliation.cit.conclusion_state`
- `cn.reconciliation.cit.blocking_issue_count`
- `cn.reconciliation.cit.difference_issue_count`
- `cn.reconciliation.cit.warning_issue_count`
- `cn.reconciliation.cit.detail`

事实提供器只接受同一档案、完全相同期间的唯一当前成功结果，并重新核对快照结构、计数、来源 SHA-256 和覆盖全部金额及问题内容的最终结果 SHA-256。运行详情可以发起精确期间规则扫描，相关整改任务的验证复扫沿用原风险期间。

当前安装数据没有新增未经真人专业签核的企业所得税规则。事实接入只是为后续完成官方来源治理、测试、独立审批和中国财税专业签核的规则提供可靠输入；没有生效规则时，系统不会制造风险或合规结论。

## Odoo 原生体验

- “规则与配置”中维护企业所得税会计利润口径，使用原生表单、状态栏、附件和多公司上下文。
- “合规管理”中提供勾稽结果、发起向导和问题清单三个入口。
- 结果页首先显示红色数据阻断、黄色差异或限制、绿色带边界的一致状态。
- 审计页显示结果完整性徽标；汇总金额、问题内容或来源指纹被篡改时，页面立即显示红色异常并阻止规则取数。
- 账簿利润、申报账税链、应补缴款和应退退库分区展示，避免把不同方向混成一个金额。
- 问题逐项显示来源、严重程度、差异金额、原因和下一步动作，并可追溯到口径、申报和缴退税来源。
- 普通合规用户按允许公司只读；合规管理员维护口径并发起后台勾稽。底层会计凭证明细仍受 Odoo 会计权限控制。

- 最终空库新装执行 182 个运行时测试方法，Odoo 统计 206 项，结果为 `0 failed / 0 errors`。
- 从 `19.0.1.20.0` 升级至 `19.0.1.21.0` 时已执行 `19.0.1.21.0` 后迁移，并再次通过 182 个运行时测试方法、206 项 Odoo 统计，结果为 `0 failed / 0 errors`。
- 真实数据隔离副本升级前后均为 15,589 张凭证、44,651 条分录，借贷合计均为 4,833,726,766.89；`account_move` 全行 SHA-256 `09061bbb...16543` 和 `account_move_line` 全行 SHA-256 `f8340bb8...382c` 完全一致。

## 当前边界与下一步

本里程碑不是企业所得税计算器，也不会从会计科目名称自动推断税法调整。纳税调增、调减、税率、优惠、抵免、亏损、资产税会差异、关联交易和跨境事项必须由完成官方来源治理和专业签核的规则处理，并结合企业依法取得的数据和人工复核。

下一阶段应基于本勾稽快照设计首批企业所得税数据准备度和内部控制候选规则，交由中国财税专业人员审核；在正式来源、真实企业适用性和证据不足时，系统必须继续输出数据不足或待复核，而不是“通过”。
