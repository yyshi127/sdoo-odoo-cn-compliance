# 里程碑 09：电子发票与 Odoo 会计凭证勾稽

## 目标

把当前有效的规范化电子发票台账与同一公司 Odoo 账簿建立可解释、可复核、可追溯的候选关系，明确显示数据缺口、未匹配、多候选、部分匹配、已确认匹配和确认后账簿变化。系统只建立合规关系，不写入或改写 `account.move`。

## 交付范围

- 中国国家包版本升级为 `19.0.1.7.0`，运行态能力 `reconciliation` 设为启用。
- 新增后台勾稽批次、勾稽事项、匹配候选及两个原生 Odoo 向导。
- 同一合规档案和精确期间只允许一个待处理或处理中的批次，数据库唯一索引防止并发绕过。
- 队列使用 `FOR UPDATE SKIP LOCKED` 有界领取任务；失败批次不会替代上一份成功结果。
- 新成功批次只替代同一档案、同一开始日和结束日的上一成功批次。
- 普通合规用户只读；合规管理员可发起、确认、拒绝和撤销；人工指定还要求会计用户权限和不少于 10 个字符的说明。
- 所有模型按允许公司隔离，审计结果不可手工创建、任意改写或删除。

## 两种匹配模式

### 供应商账单级

适用于规范化电子发票与 Odoo `in_invoice` 或 `in_refund` 的关系。引擎比较：

| 依据 | 最高分 | 说明 |
| --- | ---: | --- |
| 发票号码 | 45 | 精确或受控包含匹配 |
| 销售方识别号、名称 | 30 | 识别号优先，名称仅作保守精确比较 |
| 币种 | 5 | 币种不一致会扣分，金额不跨币种硬比 |
| 价税合计、税额 | 30 | 使用对应币种精度判断 |
| 日期、红蓝状态、过账状态 | 15 | 草稿凭证不能成为高可信候选 |

单一高可信候选只显示“待确认建议”，不会自动确认。发票级关系只能确认供应商账单或供应商贷项通知单。

### 源会计凭证级

适用于财政部电子凭证中已经携带一个或多个会计凭证关联的情况。每个源凭证分别比较凭证编号、入账日期、本位币、借贷合计、摘要和过账状态。一张电子发票可以确认多个源凭证关系；系统不强迫把真实的多凭证结构压成一对一关系。同一源凭证只能确认一个 Odoo 候选，且不能与发票级模式混用。

## 状态与数据门禁

勾稽事项明确区分：

- `数据缺口`：阻断自动候选。
- `未找到候选`：账簿范围内没有达到最低分的记录。
- `待确认建议`：仅有一个高可信候选。
- `多候选待判断`：没有唯一高可信结论或存在多个高可信候选。
- `部分匹配`：多源凭证场景仅确认了部分关系。
- `已匹配`：授权人员完成全部所需确认。
- `已复核未匹配`：所有候选均被明确拒绝。

批次另外显示“无可用源数据 / 源数据可勾稽 / 源数据存在阻断”。期间没有当前有效电子发票时，技术任务可以完成，但结果会明确说明不能形成匹配、未匹配或无风险结论，并跳过无意义的账簿候选扫描。

以下情况阻断候选生成：

- 规范化结果本身为错误。
- 缺少发票号码或价税合计。
- 电子发票会计主体与当前 Odoo 公司统一社会信用代码不一致。
- 真实性工具已经明确返回失败。
- 源文件封存完整性不再有效，或声明记录数与当前规范化文档数不一致。
- 当前评估范围出现相同销售方、发票号码和红蓝状态的重复源发票。

公司未维护统一社会信用代码、真实性尚未验证或暂不可验证、覆盖范围不完整、单人复核例外会作为警告保留，不会被误写成“已验证”或“完整覆盖”。

## 可审计性

每个成功批次保存四层审计依据：

1. 当前规范化电子发票集合 SHA-256。
2. 评估账簿完整范围 SHA-256，包含凭证核心字段、借贷合计、行数和最后变化时间。
3. 引擎初始候选及评分结果 SHA-256。
4. 每个候选对应 Odoo 凭证快照及 SHA-256。

确认前会重新计算凭证快照，只允许确认已过账且快照未变化的候选。确认后若凭证或借贷行变化，事项会显式显示“确认后账簿已变化”，要求重新勾稽。确认、拒绝、撤销和人工指定均写入不可改写的合规审计事件。

## 用户体验

- 菜单和动作沿用 Odoo 原生导航，入口为“账票勾稽”“发起账票勾稽”和“账票勾稽批次”。
- 列表通过徽章、行颜色和默认筛选突出待处理事项。
- 事项表单先显示结论和下一步，再展示候选评分、金额差异、源凭证及审计指纹。
- 无会计查看权限的合规用户只能看受控快照，不会因 `account.move` 权限不足导致页面失败。
- 有只读会计权限的用户可以打开原始 Odoo 凭证；人工指定仍要求完整会计用户权限。

## 自动化校验

已编写 18 个 Odoo 运行时测试场景，覆盖：

- 受控创建门禁、并发批次和取消后重试。
- 高可信供应商账单候选及评分依据。
- 确认审计、确认后账簿变化检测。
- 多源会计凭证、部分匹配和完整匹配。
- 主体不一致、真实性失败、重复源发票和无候选。
- 多候选、草稿确认拦截、人工指定权限与说明。
- 拒绝与撤销、失败重试不替代、模式互斥和多公司隔离。

`tools/validate_addon.py` 已将模型导入、清单、迁移、队列、并发索引、快照字段、ACL、公司规则、关键界面和最少测试数纳入持续门禁。

## 未完成项

- 上述测试已纳入 `19.0.1.9.0` 的 Odoo 19 隔离全新安装和当前版本更新验收；完整运行时矩阵见里程碑 11。
- 已验证目标 Linux 环境中的原生队列领取逻辑，尚未验证多工作进程压力、真实会计大数据量性能和前端人工交互。
- 电子发票、增值税申报和缴税凭证之间的期间勾稽已在里程碑 11 建立，完整申报调节表仍未完成。
- 尚未把差异事项自动转为经过规则治理的风险、整改任务、证据和复扫闭环。
- 正式中国财税规则仍需官方原文快照、有效期治理、测试、独立审批和中国财税专业人员签核。

因此，本里程碑只证明账票匹配技术和审计边界已经形成代码基线，不代表整个中国财税合规包已经完成，也不构成抵扣、税前扣除、申报或税务合规结论。
