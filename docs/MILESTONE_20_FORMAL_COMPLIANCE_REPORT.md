# 里程碑 20：中国正式合规管理报告

## 目标

将已完成的中国合规评估从动态查看页提升为可编制、可独立批准、可冻结、可验证、可替代和可撤回的正式管理报告，同时继续保持税务结论边界。

交付版本：`sudo_country_pack_cn 19.0.1.17.0`。

正式报告是组织内部的受控管理层报告，不是纳税申报表、税务鉴证报告、法律意见、审计意见或税务机关认定。“已签发”只表示组织内部完成了受控批准。

## 生命周期

报告使用以下不可逆主流程：

`编制中 -> 待独立批准 -> 已签发 -> 已被替代 / 已撤回`

- 只有合规管理员可以从已完成的中国评估编制报告。
- 提交后，报告内容和来源快照不可改写；批准人只能填写批准意见、退回或签发。
- 已签发报告不能修改或删除。后续修订必须建立新版本，新版本签发时替代原当前版本。
- 撤回只改变生命周期状态并记录原因、人员和时间，不删除或重写原 PDF。
- 已签发、已替代和已撤回记录只能下载签发时封存的 PDF，不允许重新渲染一个外观相似但字节不同的“正式”文件。

## 提交门禁

提交独立批准前必须同时满足：

1. 来源评估已经完成，具有明确期间、规则版本和风险结果。
2. 管理层摘要和范围说明完整。
3. 规则结果没有待复核官方来源或缺失真人专业签核的警告。
4. 所有需要人工判断的风险结果已经确认或标记为需要整改。
5. 税务影响复核不存在完整性异常。
6. 已验证证据的当前内容与封存校验和一致。
7. 已指定具有当前公司权限的报告批准人。
8. 编制、提交与批准由同一人承担时，必须记录完整的受控例外理由。
9. 存在数据限制、未知结果、执行错误、待复核或无法量化税务影响时，必须填写限制说明。
10. 存在失败结果、需要整改的人工结论或未关闭整改任务时，必须填写管理层整改回应。

复扫评估即使规则结果已经通过，只要原整改任务仍待授权人员确认，报告仍显示“需要整改”，不会提前形成清晰结论。

## 冻结内容

提交时生成 `sdoo.cn.compliance-report.v1` 快照并计算 SHA-256。快照包含：

- 报告身份、版本、范围、管理层说明、编制人、批准人和替代关系。
- 公司、档案、期间、数据充分性和评估汇总。
- 规则版本、规则哈希和专业签核状态。
- 事实值、质量、聚合方法、提供者版本和事实哈希。
- 风险结果、官方来源快照、专业复核快照、人工复核和结果哈希。
- 整改任务、负责人、期限、复扫状态和完成说明。
- 证据状态、封存哈希、当前哈希和完整性结果。
- 税务影响事项及潜在少缴、潜在多缴、期间错配三个独立方向；不计算净额。
- AI 分析只冻结提供者、模型、版本、状态和记录哈希等元数据，不把 AI 文本当作正式结论。

提交后源评估、事实、风险、任务、证据或税务影响发生变化时，系统显示“源资料已变化”，并阻止签发，必须退回后重新提交。

## 独立批准与三重完整性

签发只能由报告中指定且具有“中国合规报告批准人”权限的用户执行。批准意见不少于 20 个字符；职责未分离时还必须记录例外理由。

系统分别维护三类指纹：

- 内容快照 SHA-256：绑定提交时的完整报告来源。
- 批准 SHA-256：绑定内容快照、提交人、提交时间、批准人、签发时间、批准意见和同人例外。
- PDF SHA-256：绑定签发时实际封存的 PDF 字节。

批准元数据或 PDF 附件后续被绕过 ORM 改写时，界面立即显示完整性异常并禁止下载正式报告。正常业务操作不能直接写入报告身份、状态、快照、批准、PDF 和汇总字段。

## Odoo 原生界面

- `合规 -> 正式报告` 默认显示编制中、待批准和当前签发记录，历史替代与撤回记录可通过筛选查看。
- 列表直接显示风险数量、未关闭整改、报告结论、生命周期、批准人和完整性状态。
- 表单使用 Odoo 原生状态栏、徽章、警示条、统计按钮、分组和页签。
- 非指定批准人不显示退回和签发按钮。
- 草稿和待批准 PDF 醒目标记“预览稿，尚未签发”。
- 已签发后只提供经过批准与 PDF 双重完整性校验的封存文件下载。
- 普通合规用户按允许公司只读；合规管理员编制和撤回；报告批准人独立退回或签发。

## 升级兼容

升级迁移登记版本和能力元数据，不创建报告、不发布规则、不修改会计凭证，也不替用户形成批准或签发记录。报告编号使用独立序列，同一评估内的版本号具有数据库唯一约束。

本里程碑同时拆分了专业复核包的存储与非存储计算方法，消除了 Odoo 注册表中的混合 `store` 警告，并区分“复核包记录”和“当前复核包”的界面标签。

## 验收结果

- 本地 Python/XML 编译、静态契约、差异检查和 `31` 项纯数据契约测试通过。
- 正式报告定向执行 `12` 个运行时测试方法，Odoo 统计 `14` 项，`0 failed / 0 errors`。
- 隔离空库新装执行 `158` 个运行时测试方法，Odoo 统计 `180` 项，`0 failed / 0 errors`。
- 从 `19.0.1.16.0` 升级到 `19.0.1.17.0` 后执行同一全量测试，迁移成功，仍为 `0 failed / 0 errors`。
- `odoo_2601` 隔离副本安装和最终更新后仍有 `15,589` 张会计凭证和 `44,651` 条会计分录；凭证内容摘要、分录内容摘要及借贷合计与只读源库完全一致。
- 事务内完成真实 QWeb/wkhtmltopdf 签发，生成有效 `%PDF` 文件；内容快照、批准记录和 PDF 三项完整性均为正常，测试数据随后回滚。
- 主 Odoo 服务全程保持运行；没有修改共享底座、新加坡国家包、业务数据库或生产 Python 依赖。

## 当前边界与下一步

正式报告技术链路已经具备，但当前七项官方来源仍待独立复核，七条候选规则仍没有真人中国财税专业签核或发布资格。因此系统当前不能生成真实企业的正式税法合规结论。

后续顺序是：完成官方来源治理和真人专业签核，发布首批受控规则，在隔离真实数据副本执行完整业务验收，再建立大数据量、并发、队列、报告批量读取和长期附件完整性性能基线。
