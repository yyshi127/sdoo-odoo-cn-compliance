# M29 中国个人所得税受控规则闭环与申报缴退税档案

交付版本：`sudo_country_pack_cn 19.0.1.26.0`。

## 1. 目标与设计决策

M29 在 M28 个人所得税工资、账簿、申报与缴退税勾稽之上，完成两段受控链路：

1. 将精确期间个税勾稽结果作为不可改写的聚合事实接入通用规则引擎，形成规则扫描、风险、人工复核、整改、证据和验证复扫闭环；
2. 复用通用申报生命周期，封存个税扣缴申报、应补缴款或应退退库、正式回执和审计摘要。

本里程碑不计算工资、扣除、税率或税额，不推断法定期限和企业适用性，不连接税务机关，也不把算术一致、回执存在或档案封存解释为个人所得税合规结论。

## 2. 精确期间聚合事实

新增五项事实：

- `cn.reconciliation.iit.conclusion_state`；
- `cn.reconciliation.iit.blocking_issue_count`；
- `cn.reconciliation.iit.difference_issue_count`；
- `cn.reconciliation.iit.warning_issue_count`；
- `cn.reconciliation.iit.detail`。

事实适配器只接受同一公司、同一合规档案和完全相同起止日期的唯一当前成功批次。来源正在重算、存在重复当前结果、来源快照或完整结果 SHA-256 异常、问题数量不一致时，事实固定降级为数据不足、过期或提取错误，不允许形成伪通过。

详情使用 `sdoo.cn.reconciliation.iit-period.fact.v1` 聚合契约，验证口径、账簿、工资、申报和缴退税五类来源摘要及完整结果摘要。契约不包含姓名、证件、手机、地址、银行账号、源明细键或人员键。

## 3. 候选规则与治理边界

新增两条安装态草稿：

- `CN-DATA-IIT-RECON-001`：个税勾稽数据准备度；
- `CN-IIT-RECON-CTRL-001`：个税勾稽差异复核内部控制。

受控处理器 `cn.iit.reconciliation.review.v1` 明确区分四种情形：

- 来源阻断：待确认；
- 金额或人数差异：失败并进入人工复核；
- 无差异但仍有提示：待确认；
- 无阻断、无差异、无提示：通过，但仍保留结论边界和人工复核要求。

两条规则具有七个正反和三态测试案例、两份专业复核候选包和六条引用定位。新增三项官方网址仅是 URL 候选，没有原文快照、SHA-256、独立审批或真人专业签核。升级迁移只为仍处于原始草稿和待审批状态的候选规则补充关联，不覆盖用户已经治理或调整的记录。

安装数据继续保持十一条规则全部为 `draft / pending`，没有测试规则、伪造快照或伪造专业签核。闭环运行时测试会临时创建一条完全受控的生效规则，事务结束后不会进入产品数据。

## 4. 风险、整改与验证复扫

个税勾稽成功批次提供原生“发起规则扫描”动作。扫描按勾稽批次的精确期间生成评估，风险保留规则性质、事实摘要、来源完整性和结论边界。

运行时闭环验证：

`成功勾稽 -> 规则扫描 -> 待确认风险 -> 整改任务 -> 正式证据 -> 替代勾稽 -> 精确期间验证复扫 -> 风险关闭`

整改复扫不会使用当前日期、模糊月份或累计期间替换原风险期间。若替代勾稽仍不满足条件，风险不得自动关闭。

## 5. 个税申报缴退税档案

扩展通用 `sudo.compliance.filing`，把当前成功个税勾稽桥接为受控档案，不创建第二套申报状态机。建档要求：

- 当前公司和档案具有适用且经过人工确认的 `CN-IIT-WHT` 义务；
- 截止日由人员明确确认，并绑定经过治理的官方依据；
- 存在精确期间、唯一且可用的个税扣缴申报；
- 申报提交具有经过正式证据流程验证的税务机关回执；
- 应补方向具有足额、有效且经验证的缴款证明；
- 应退方向具有足额、有效且经验证的退库回执。

系统分别保存：

- `sdoo.cn.iit-withholding-filing-archive.v1` 申报聚合快照；
- `sdoo.cn.iit-withholding-settlement-archive.v1` 缴退税聚合快照；
- 申报、缴款或退库正式证据摘要；
- 来源当前性、内容完整性和档案 SHA-256。

应补与应退方向互斥且不轧差。应补只比较有效缴款本金；应退只比较已退库本金。冲正、退库、利息和滞纳金分别保留，不会混入本金或伪装为“已付款”。来源出现新批次或内容变化时，历史档案保留并显示已被替代或完整性异常。

## 6. 权限、隐私与原生界面

- 合规管理员创建档案、确认截止日、选择受控来源并封存正式回执；
- 普通合规用户按允许公司只读查看聚合结论、状态和审计摘要；
- 个税申报、缴退税源记录和敏感关联仅向合规管理员显示；
- 跨公司勾稽、来源、证据或人员关系被模型约束和记录规则拒绝；
- 事实与申报档案不保存自然人身份字段。

界面使用 Odoo 原生按钮、状态栏、警示条、页签、统计按钮、列表、搜索和多公司上下文。个税勾稽表单可直接发起规则扫描或打开申报档案；申报档案分别展示申报归档、应补缴款、应退退库、正式证据和完整性状态。

## 7. 完整性修复

隔离测试发现：数据不足批次在内存构建时，空 Many2one 被序列化为 `null`，ORM 重新读取后被序列化为 `false`，导致完整结果 SHA-256 不一致。M29 将关系记录统一规范化为记录 ID 或 `null`，并新增数据不足结果完整性和事实返回断言。

该修复只规范化空关系字段的审计表示，不修改业务来源、会计凭证或历史金额。

## 10. 明确未交付内容与下一步

M29 不交付：

- 已治理、独立审批并经真人中国财税专业人员签核的个税法定规则；
- 工资、专项扣除、税率、税额、居民身份或所得项目计算；
- 法定截止日、主管机关和企业适用性的自动判定；
- 税务机关接口、自动申报、自动缴款或自动退税；
- 申报正确、足额缴税、可退税或个人所得税合规结论。

下一阶段仍应优先完成官方来源快照治理、独立审批和真人中国财税专业签核，再扩展其他税种、地方规则、法定期限参数、外部格式适配和更完整的专业复核体验。未经治理的候选规则不能为了演示而直接生效。
