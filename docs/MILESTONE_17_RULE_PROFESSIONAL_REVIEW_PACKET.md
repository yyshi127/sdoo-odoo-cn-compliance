# 里程碑 17：中国规则专业复核候选包

## 目标

把七条中国内部控制与数据准备度规则草稿整理成可供真人中国财税专业人员逐项审阅的受控候选材料，同时继续阻止系统自动批准官方来源、伪造专业意见或发布规则。

交付版本：`sudo_country_pack_cn 19.0.1.15.0`。

## 复核包结构

每个中国规则版本只允许关联一份专业复核包。复核包冻结以下候选内容并生成独立 SHA-256：

1. 适用范围。
2. 适用前提。
3. 明确排除与限制。
4. 结论边界。
5. 待专业人员回答的问题。
6. 规则已关联官方来源的逐项条款定位、引用性质、规则主张和适用说明。

当前七条规则草稿形成 `7` 份复核包和 `14` 条引用定位。引用覆盖每条规则已经关联的全部官方来源，没有把任何当前内部控制标记成“法条直接要求”。

## 候选来源定位

| 官方来源 | 候选定位范围 |
| --- | --- |
| 《中华人民共和国会计法（2024年修正）》 | 第九条、第十四条、第十五条、第十七条、第二十三条、第二十五条 |
| 《会计档案管理办法》 | 第三条、第五条、第八条至第十二条 |
| 《中华人民共和国增值税法》 | 第八条、第十条至第十六条、第二十八条至第三十四条 |
| 《中华人民共和国增值税法实施条例》 | 第五条、第十一条至第十七条 |
| 《中华人民共和国发票管理办法》 | 第十八条至第二十条 |
| 《中华人民共和国税收征收管理法》 | 第四条、第十五条至第十九条、第二十五条 |
| 电子凭证会计数据标准推广通知 | 第一部分、第二部分、第三部分第（三）项 |

这些定位只用于组织专业审阅，不是系统生成的法律意见。专业人员仍须核对已封存官方快照、现行有效性、企业适用性、特殊情形和规则结论边界。

## 发布与签核门禁

中国规则进入专业签核前必须同时满足：

- 已明确规则性质，且内部控制或数据准备度规则要求人工复核。
- 所有关联官方来源均有可发布快照、64 位 SHA-256、有效状态、独立复核人和未过期复核日期。
- 规则测试存在且全部通过。
- 专业复核包字段完整，引用只使用该规则已经关联的官方来源，并覆盖全部来源。

专业复核包进入规则业务校验和与专业签核哈希。草稿材料、引用或官方来源内容改变后，既有签核会失效，修改人会进入载荷准备人清单并生成审计事件。普通合规用户只读，规则维护人与合规管理员只能修改草稿规则的复核包。

## 原生界面与报告

- 规则版本表单显示复核包状态、签核前置缺口和打开、打印按钮。
- 复核包表单按“适用范围与边界、条款定位、专业审阅问题”组织材料。
- QWeb PDF 显示规则执行载荷、来源 URL 与哈希、引用定位、测试覆盖、专业问题和独立签核记录。
- 每份报告醒目标记“候选草案，不得用于对外合规结论”。
- 报告从单个复核包打印，不暴露列表批量打印入口。服务器当前 `wkhtmltopdf` 使用未补丁 QT，不能可靠合并多份文档；逐份打印不受影响。

## 实际验收结果

- 本地静态校验、Python/XML 编译和 `29` 项数据契约测试通过。
- 隔离空库新装执行 `138` 个运行时测试方法，Odoo 统计 `158` 项，结果为 `0 failed / 0 errors`。
- 从 `19.0.1.14.0` 基线升级后执行相同全量测试，结果仍为 `0 failed / 0 errors`。
- 隔离真实数据副本升级后仍有 `15,589` 张会计凭证和 `44,651` 条会计分录。
- 原增值税勾稽结果仍为 `succeeded / insufficient_data / invoice_tax_totals`，发票销项税额 `5.18`，结果 SHA-256 保持不变。
- 七条候选规则的 `14` 个案例全部通过，发布状态仍是“官方来源待治理”，没有规则获得专业签核或发布资格。
- 七项官方来源保持 `pending_review`，审核人和审核时间为空，没有自动批准。
- 七份 HTML 报告均包含候选边界和复核包哈希；七份单独 PDF 均成功生成有效 `%PDF` 文件。

## 当前正确状态

复核材料已经达到“可交给专业人员审阅”的技术状态，但规则尚未达到“可以正式发布”的治理状态。下一步必须由不同人员逐页核对七份官方快照并审批来源，再由具备可验证资质的中国财税专业人员回答复核问题、记录意见和证据 SHA-256。系统不得代替这两类真人判断。
