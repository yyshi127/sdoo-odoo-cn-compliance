# Sdoo Odoo China Compliance

Odoo 19 中国财税合规插件工程。

## 目标

基于真实 Odoo 会计与业务数据，建设可安装、可升级、可审计的中国财税合规国家包，形成以下受控闭环：

`企业档案 -> 适用义务 -> 数据采集与勾稽 -> 规则扫描 -> 风险 -> 人工复核 -> 整改 -> 证据 -> 验证复扫 -> 报告与申报缴款档案`

## 模块边界

- `sudo_global_finance`：外部依赖，提供国家无关的合规底座和规则治理能力。
- `sudo_country_pack_cn`：本仓库交付的中国国家包。
- 中国专属规则、参数、事实语义和整改指引不得下沉到通用底座。
- 新加坡国家包不属于本仓库，也不在本项目中修改。

## 安全边界

- 不提交真实数据库、filestore、客户附件、业务导出或备份。
- 不提交服务器地址、密码、密钥、令牌或连接器凭据。
- 正式规则必须具有官方来源快照、有效期、测试、独立审批和中国财税专业签核。
- 数据不足必须显式输出，禁止把缺失数据解释为合规通过。
- AI 只提供受控解释和操作引导，不替代规则引擎或专业判断。

## 开发状态

当前已完成可安装国家包骨架、国家初始化、候选义务、十一项只读基础事实、二十项勾稽事实、十一条内部控制与数据准备度规则草稿，以及按有效期管理的中国纳税人身份快照。身份快照具有来源、附件、管理人员核验、SHA-256 完整性和多公司隔离控制。

国家包还登记了十二项官方网址候选来源，并将相关规则草稿与候选来源建立可追溯关联。候选记录全部保持草稿、无原文快照、无哈希、无审批，不属于有效依据。规则草稿只验证统一规则 DSL、测试与发布门禁，不属于正式中国财税规则，也不会进入正式评估。

当前版本还提供受控外部数据集登记，覆盖电子发票与电子凭证、增值税申报、税款缴纳、个税扣缴、银行证据和其他监管数据。数据集记录依法取得依据、覆盖范围、原始附件、真实性验证状态、SHA-256 封存校验、独立复核或单人例外，以及不可改写的替代版本链。封存不等于税务真实性验证或税法结论。

电子发票规范化台账和受控解析运行契约也已建立，能够保留发票头、金额、真实性与覆盖状态，以及一张电子发票关联多张会计凭证、每张凭证包含多条借贷分录的结构。解析结果不可手工创建或改写；失败重跑不会替代上一份成功结果。

可选插件 `sudo_country_pack_cn_einvoice_xbrl` 已实现受控财政部分类标准包、Arelle 2.42.1 离线隔离解析、后台任务、版本锁定和兼容处理审计。财政部官方专票、普票样例均在隔离 Odoo 运行时经真实子进程和 cron 队列验证为 0 警告、0 错误，并成功生成规范化会计单据和借贷分录。解析成功仍不等于发票真实、可抵扣、可税前扣除或已经正确申报。

电子发票与 Odoo 会计凭证勾稽工作台已经形成代码基线。系统支持供应商账单级和源会计凭证级两种模式，生成可解释候选，显式区分数据缺口、未匹配、单一建议、多候选、部分匹配和已匹配，并保留账簿快照与人工决策审计。系统不会修改会计凭证，也不会把匹配关系解释为抵扣或申报结论。

增值税申报与税款缴纳标准化台账也已形成代码基线。受控 JSON 契约严格区分零值与缺失，拒绝未知字段、重复 JSON 字段和数量不一致，保留来源、版本、质量问题与多层 SHA-256 审计指纹，并禁止保存未脱敏付款账号。该能力不连接税务机关，不自动提交申报或执行付款。

增值税期间四方勾稽也已形成代码基线。系统比较 Odoo 已过账客户及供应商发票税额、受控电子发票、唯一有效增值税申报和有效缴税净额，显式区分数据阻断、金额差异和带限制的一致结果，并保留来源快照指纹、问题说明、下一步建议和成功替代审计。缺失、部分覆盖、主体不明、重复或币种不一致不会被解释为通过；金额一致也不等于税务合规结论。

账票勾稽和增值税四方勾稽现已通过不可改写事实快照接入通用规则引擎。事实适配只接受同一档案、完全相同期间的唯一当前成功批次；正在重算、期间不一致、重复当前结果、审计指纹缺失或批次计数不一致都会阻止正式判断。成功批次可通过原生按钮发起精确期间规则扫描，相关整改任务的验证复扫会沿用原风险期间，不会把不同月份静默汇总。

核心中国包 `19.0.1.14.0` 已建立增值税控制科目和申报调整治理层。系统按有效期读取经过证据核验的销项、进项控制科目，以已过账总账分录计算发生额，再叠加精确期间、经过审批的申报调整形成申报比较口径；发票税额继续独立用于账票比较和发票与控制科目内部勾稽。缺少完整双向映射、部分期间覆盖、配置或证据完整性失效、重复映射等情况会阻断申报比较，不会静默退回较弱口径。
