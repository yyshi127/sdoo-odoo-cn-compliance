# Sdoo Odoo China Compliance

Odoo 19 中国财税合规插件工程。

## 目标

基于真实 Odoo 会计与业务数据，建设可安装、可升级、可审计的中国财税合规国家包，形成以下受控闭环：

`企业档案 -> 适用义务 -> 数据采集与勾稽 -> 规则扫描 -> 风险 -> 人工复核 -> 整改 -> 证据 -> 验证复扫 -> 报告与申报缴款档案`

## 模块边界

- `sudo_global_finance`：外部依赖，提供国家无关的合规底座和规则治理能力。
- `sudo_country_pack_cn`：本仓库交付的中国国家包。
- 中国专属规则、参数、事实语义和整改指引不得下沉到通用底座。
- 新加坡国家包不属于本仓库，也不在本项目中修改。

## 安全边界

- 不提交真实数据库、filestore、客户附件、业务导出或备份。
- 不提交服务器地址、密码、密钥、令牌或连接器凭据。
- 正式规则必须具有官方来源快照、有效期、测试、独立审批和中国财税专业签核。
- 数据不足必须显式输出，禁止把缺失数据解释为合规通过。
- AI 只提供受控解释和操作引导，不替代规则引擎或专业判断。

## 开发状态

当前已完成可安装国家包骨架、国家初始化、候选义务、十一项只读基础事实、十项勾稽事实、七条内部控制规则草稿，以及按有效期管理的中国纳税人身份快照。身份快照具有来源、附件、管理人员核验、SHA-256 完整性和多公司隔离控制。

国家包还登记了七项官方网址候选来源，并将相关规则草稿与候选来源建立可追溯关联。候选记录全部保持草稿、无原文快照、无哈希、无审批，不属于有效依据。规则草稿只验证统一规则 DSL、测试与发布门禁，不属于正式中国财税规则，也不会进入正式评估。

当前版本还提供受控外部数据集登记，覆盖电子发票与电子凭证、增值税申报、税款缴纳、个税扣缴、银行证据和其他监管数据。数据集记录依法取得依据、覆盖范围、原始附件、真实性验证状态、SHA-256 封存校验、独立复核或单人例外，以及不可改写的替代版本链。封存不等于税务真实性验证或税法结论。

电子发票规范化台账和受控解析运行契约也已建立，能够保留发票头、金额、真实性与覆盖状态，以及一张电子发票关联多张会计凭证、每张凭证包含多条借贷分录的结构。解析结果不可手工创建或改写；失败重跑不会替代上一份成功结果。

可选插件 `sudo_country_pack_cn_einvoice_xbrl` 已实现受控财政部分类标准包、Arelle 2.42.1 离线隔离解析、后台任务、版本锁定和兼容处理审计。财政部官方专票、普票样例均在隔离 Odoo 运行时经真实子进程和 cron 队列验证为 0 警告、0 错误，并成功生成规范化会计单据和借贷分录。解析成功仍不等于发票真实、可抵扣、可税前扣除或已经正确申报。

电子发票与 Odoo 会计凭证勾稽工作台已经形成代码基线。系统支持供应商账单级和源会计凭证级两种模式，生成可解释候选，显式区分数据缺口、未匹配、单一建议、多候选、部分匹配和已匹配，并保留账簿快照与人工决策审计。系统不会修改会计凭证，也不会把匹配关系解释为抵扣或申报结论。

增值税申报与税款缴纳标准化台账也已形成代码基线。受控 JSON 契约严格区分零值与缺失，拒绝未知字段、重复 JSON 字段和数量不一致，保留来源、版本、质量问题与多层 SHA-256 审计指纹，并禁止保存未脱敏付款账号。该能力不连接税务机关，不自动提交申报或执行付款。

增值税期间四方勾稽也已形成代码基线。系统比较 Odoo 已过账客户及供应商发票税额、受控电子发票、唯一有效增值税申报和有效缴税净额，显式区分数据阻断、金额差异和带限制的一致结果，并保留来源快照指纹、问题说明、下一步建议和成功替代审计。缺失、部分覆盖、主体不明、重复或币种不一致不会被解释为通过；金额一致也不等于税务合规结论。

账票勾稽和增值税四方勾稽现已通过不可改写事实快照接入通用规则引擎。事实适配只接受同一档案、完全相同期间的唯一当前成功批次；正在重算、期间不一致、重复当前结果、审计指纹缺失或批次计数不一致都会阻止正式判断。成功批次可通过原生按钮发起精确期间规则扫描，相关整改任务的验证复扫会沿用原风险期间，不会把不同月份静默汇总。

核心中国包 `19.0.1.14.0` 已建立增值税控制科目和申报调整治理层。系统按有效期读取经过证据核验的销项、进项控制科目，以已过账总账分录计算发生额，再叠加精确期间、经过审批的申报调整形成申报比较口径；发票税额继续独立用于账票比较和发票与控制科目内部勾稽。缺少完整双向映射、部分期间覆盖、配置或证据完整性失效、重复映射等情况会阻断申报比较，不会静默退回较弱口径。

里程碑 13 进一步在 `odoo_2601` 的隔离只读副本完成真实会计数据验收：原生菜单、档案、空状态、四方勾稽详情和审计快照均通过浏览器检查；`1440×900`、`1366×768`、`1280×720` 与 `1024×768` 均无页面级横向溢出。真实月度样本在缺少电子发票、申报和缴税受控来源时，事实桥接稳定返回“数据不足”及三项阻断，没有形成伪通过；普通合规用户的多公司读取隔离和只读权限也已验证。

里程碑 14 已将控制科目、申报调整、期间勾稽和规则事实串成可追溯链路，并对旧版成功批次执行兼容迁移。空库新装和从 `19.0.1.11.0` 升级两条路径均通过 123 个运行时测试方法，Odoo 统计 141 项，结果为 `0 failed / 0 errors`。

里程碑 15 新增中国规则性质和发布就绪治理。系统明确区分法定义务、税额计算、申报与缴款时限、内部控制和数据准备度；规则存在版本后性质不可改写，并进入规则校验和及专业签核哈希。原生规则与风险页面会显示性质、完整发布阻断和结论边界。当前七条草案被明确分类为内部控制或数据准备度，仍全部保持未发布状态；没有测试规则或伪造专业签核进入安装数据。空库新装和从 `19.0.1.12.0` 升级两条路径均通过 129 个运行时测试方法，Odoo 统计 147 项，结果为 `0 failed / 0 errors`；真实数据副本的 15,589 张凭证、44,651 条分录及原勾稽结果校验和保持不变。下一阶段是治理官方来源并形成首批可供真人专业签核的规则候选，随后继续完善风险金额、增值税调节表、正式报告和大数据量性能；可选 XBRL 插件仍需单独完成运行时验收。

里程碑 16 对七项官方来源执行了服务器端 TLS、HTTP、内容类型和大小技术审计。全国人大 PDF 的过期 TLS 证书和财政部旧页面的 HTTP 502 没有被绕过，而是分别替换为财政部《会计法》现行全文页和中国政府网国务院公报页。升级迁移只会修正仍未采集的原始草稿候选，已形成快照或被用户调整的来源不会被覆盖。安装数据继续不包含网页正文、哈希、审批或专业签核，技术可采集不等于法律内容已经复核。

里程碑 17 为七条中国内部控制与数据准备度草稿建立了七份专业复核候选包和十四条官方来源定位。适用范围、前提、排除、结论边界、专业问题和引用关系进入规则及专业签核哈希；来源有效性、规则测试和复核包完整性成为专业签核前置门禁。原生表单和单份 QWeb PDF 均醒目标记候选边界。空库新装和从 `19.0.1.14.0` 升级均通过 138 个运行时测试方法，Odoo 统计 158 项，结果为 `0 failed / 0 errors`；真实数据副本的 15,589 张凭证、44,651 条分录和原增值税勾稽结果保持不变。七项来源仍待独立复核，七条规则没有专业签核或发布资格。

里程碑 18 新增受控税务影响复核层和增值税调节与税务影响报告。系统允许把同一经济事项涉及的多条规则结果和勾稽问题归并到一份复核事项，每条来源只能归入一份未取消事项；初步金额必须具有计算过程、限制、工作底稿和系统内证据，并经过独立复核或记录同人例外后才成为已复核金额。潜在少缴、潜在多缴和期间错配影响分别列示，不计算净额；待复核、无法量化及 SHA-256 完整性异常事项不进入金额汇总。空库新装和从 `19.0.1.15.0` 升级均通过 146 个运行时测试方法，Odoo 统计 166 项，结果为 `0 failed / 0 errors`。真实数据副本的 15,589 张凭证、44,651 条分录和原勾稽 SHA-256 均保持不变；事务内全流程成功生成单份 PDF，证据篡改后已复核金额立即退出汇总。该报告是受控工作底稿，不是纳税申报表、税务机关认定或法律意见。

里程碑 19 完成可选 XBRL 插件 `19.0.1.1.0` 的隔离 Odoo 新装、升级、真实工作进程和 cron 队列验收。财政部“全面数字化电子发票（推广应用版）”官方 ZIP 原始 SHA-256 与登记值一致；专票、普票分别解析出 39/33 个事实和 3/2 条会计分录，均为 0 警告、0 错误。兼容处理不再整体重写 XSD，而是在 XML 语义检查后只修剪目标 `roleURI` 的边缘空白；同一官方包在 Windows Python 3.11 与 Linux Python 3.12 产生相同工作副本 SHA-256。可选插件的 17 个运行时测试方法、Odoo 统计 21 项全部通过。生产 Odoo Python 环境仍需在受控维护窗口安装固定的 `arelle-release==2.42.1`，本里程碑没有修改主服务依赖或向业务数据库部署。

里程碑 20 交付核心中国包 `19.0.1.17.0` 的正式合规管理报告。已完成评估可进入编制、独立批准、签发、替代和撤回生命周期；规则、事实、风险、整改、证据、税务影响和 AI 元数据形成可解释快照，并分别保存内容、批准和封存 PDF 三类 SHA-256。源资料变化、待复核结果、专业签核警告、证据或税务影响完整性异常均会阻止签发；少缴、多缴和期间错配继续分列且不计算净额。空库新装及从 `19.0.1.16.0` 升级均通过 158 个运行时测试方法，Odoo 统计 180 项，结果为 `0 failed / 0 errors`；真实数据副本的 15,589 张凭证、44,651 条分录、借贷合计和内容摘要保持不变，真实 wkhtmltopdf 签发及三重完整性校验通过。当前候选规则仍未完成真人专业签核，技术上可签发不等于已经具备真实企业税法合规结论。
